# UCC 专项评审与重新设计：气候描述、分类和验证

日期：2026-09-17；代码核对基线 `450981a`（v0.37.0）。评审对象：2026-09-14 设计提案（清理后的保留部分 = [design-anchors.md](../design-anchors.md)，全文见 git 历史）。本文合并原专项评审与 rethink 方案，是 UCC 评审、设计建议和验证计划的唯一维护正文（2026-09-24 自 private/reviews 迁入库）。

**已确认前提：接受 Köppen 的局限性，不要求 UCC 精确复现 Köppen。** 下述 Cfa/Cfb 反例说明分类码不能无损反推 Köppen，不把这项差异本身视为 UCC 失败。本文保留独立命名和跨世界描述的目标，调整实现范围与验收方式。

## 1. 总判断

**需要 rethink，但应缩小首期承诺，而不是继续增加分类规则。** 保留“跨世界、逐地点、时间序列优先、温度与水分分开”的目标；把交付物改为：

```text
气候序列与来源
    → 有单位、有效域和时间定义的连续描述量
    → 少量、版本化、用途明确的分类 profile
    → 人类可读名称 / 简码 / 地图图例
```

UCC 的统一性应来自一致的变量含义和计算契约。Earth 与 Nacrea 的同一个温度字段始终表达温度，同一个供需比始终比较同一时段、同一物质的供给与参考需求。无需为了保持字母表一致，让“温度类”在另一颗星球变成“几何位置类”。

物理定律约束气候状态，却不会唯一决定应分成几类、在哪里切分“温和”和“炎热”。分组阈值可以是经验值或产品约定，但必须声明出处、用途和适用域。**放弃精确复现 Köppen，不等于用未经检验的新阈值替代它；应把验收目标改为信息保留、稳定性与用途价值。**

建议首期只承诺“Earth 与 Nacrea 的温度—水循环季节气候描述”。这也不是完整气候的全部：风暴、湿热、辐射暴露、日极端等暂不包含，不应宣称一个简码能覆盖所有生存或生态风险。

### 1.1 Köppen 信息丢失反例：用于界定承诺，不用于否决 UCC

原提案采用的 AI、季节集中度和热量节点没有保留全部 Köppen 亚型判据。已验证的受控反例如下：每月降水均为 100 mm，PET 年总量设为 1000 mm，两组温度仅最热月不同。

```text
序列一：14, 15, 16, 18, 19, 21, 20, 19, 18, 17, 16, 15 °C
序列二：14, 15, 16, 18, 19, 23, 20, 19, 18, 17, 16, 15 °C
```

按原提案节点解释，两者同为 `C3/C12o-Wu-Pf`；当前 `koppen_classify()` 分别得到 `Cfb`、`Cfa`。原 UCC 码未保留最热月是否达到 22°C 的区别，所以别名表无法唯一恢复 Köppen。需要时从原始月度序列独立计算 Köppen，并列保存即可。

PET 在这里是受控输入，不是对两个气候运行完整 PET 模型得到的结果；UCC 码按原提案解释，并非已有正式 UCC 实现。证据见 [反例脚本](proposal-review-probes-2026-09-17.py) 和 [结果](proposal-review-probes-2026-09-17.json)。它支持撤除无损映射承诺，不要求为了分开 Cfa/Cfb 而再加一条 UCC 规则。若报告两种分类的差异，应说明全样本与分歧来源，不通过排除不一致样本改善分数。

## 2. 文献给出的关键启发

### 2.1 最值得借鉴的是独立验证，而不是另一套字母表

Knoben、Woods 与 Freer（2018）用年干燥度、干燥度季节性和固态降水比例描述气候，再用 **1,103 个流域、16 项径流特征**检验分组的水文意义。他们强调气候可以看作连续谱，并报告其方法在水文分组上优于 Köppen。

这不证明 UCC 应照搬其三个指标，更不证明它对所有用途优于 Köppen。它提供了更合适的研究路线：**分类只用气候输入；检验使用独立的响应观测；性能判断绑定具体用途。** 本轮读到了论文摘要和作者机构页面，未取得可核对公式的全文，因此不在此声称复现其指标。

对本项目，直接由同一组 T/P 查表生成的植被结果，不能再被当作 UCC 的独立科学验证。它可以检验接口一致性，但容易形成“用自己的规则证明自己”的循环。

### 2.2 年干湿指数不能代替水分季节结构

Knoben 等（2019）的双峰降水研究指出，全球约 7% 陆地存在双峰降水季节性，并区分降水总量和降水日频率。只有第一谐波或一个“最湿月”，会漏掉对称双峰；月总量本身也无法还原降雨事件频率。

因此需要区分四件事：总量、相对集中程度、季节形状、与蒸发需求的时间配合。它们不必都占据主分类码，但不能用一个 `Pf/Pw/Ps/P2` 字段互相替代。

### 2.3 PET 的定义属于分类契约

Zomer 等（2022）的 Global-AI/PET v3 使用 FAO-56 Penman–Monteith **参考蒸散 ET0**。FAO 的标准参考面是充分供水的假想草地，草高 0.12 m、表面阻力 70 s/m、反照率 0.23；计算涉及温度、湿度、风和辐射。

这意味着 AI 的数值依赖参考需求模型。现有 Hamon 可以作为明确标注的近似输入，但不能因为结果同叫 P/PET，就宣称与另一种 ET0 的分级具有相同标定。也不能把地球草地 ET0 自动移植成甲烷世界的普适物理量。

第一阶段不必强迫整个引擎立即升级到 FAO-56。先记录 `demand_model`、参考面、单位、适用条件；支持不足时保留温度和降水描述，将水分供需轴标记为未验证或不支持。

### 2.4 几何不能替代温度，也不能替代水资源状态

Lobo 等（2023）的模拟显示，水受限陆地行星和富水海洋行星的热输送与温度梯度不同；其研究配置中，温和晨昏区并非所有同步行星的必然状态。论文还讨论冰川流动、地表和地下输水对晨昏区供水的影响。

所以：星下点角距不能推出温度类；当地 P/PET 也不能完整推出实际水资源。某地降水少却可能得到上游河水或冰川融水，这属于水文层，应与“气候供需亏缺”并列，而不改写后者的定义。

### 2.5 分类边界的不确定性需要输出

Beck 等（2023）的 Köppen-Geiger 数据集组合多个温度与降水数据源，用分类一致程度表达置信度，边界区域尤其容易不一致。确定性的分类规则仍可能接收不确定输入。

UCC 至少应保留距阈值的距离；有输入集合时再输出各类别的出现比例。不能把任意微小扰动后的跳类都当作错误，也不能只给一个颜色而隐藏边界敏感性。扰动集合的结果不是未经校准的“真实概率”。

## 3. 重新界定“物理第一性”和跨世界统一

原提案“零世界假设”“各阈值物理锚定”的表述过强。建议改为“假设显式、单位一致、适用域可检查”。

| 层次 | 应当统一的内容 | 不应承诺的内容 |
|---|---|---|
| 物理输入 | 温度、通量、时长、物质、参考表面、测量位置 | 同名文件意味着模型同样有效 |
| 描述量 | 同一公式和边界语义；支持部分有效输出 | 月均值能还原日极端、降雨频率 |
| 分类 profile | 同一版本中的阈值、名称和有效域 | 一个阈值集合适用于所有生命与溶剂 |
| 跨世界比较 | 同一描述量直接比较；匹配 profile 后比较类 | 不同 profile 下同名类别天然等价 |

原提案另有一个论证需要收回：Köppen 的算法并不要求显式三圈环流输入，慢自转也不自动让算法无法计算。问题是其经验阈值和用途能否迁移，不是算法依赖一个三圈环流开关。同理，潮汐锁定也不必然消除周年变化。

对于 θ=(T−T_ref_low)/(T_ref_high−T_ref_low)：允许作为指定参考溶剂窗口的辅助归一化量，必须保留 K 温度、参考压力和物质定义。相同 θ 不代表相同生命适宜性；真实液相稳定还涉及压力、混合物组成等。参考窗口退化或不存在时应返回不支持。首期不以 θ 取代基础温度轴。

例如把地球的 10/18°C 节点归一化为水的参考液窗中的 0.10/0.18，再迁到甲烷，仍然是经验阈值外推，不能称为“零地球标定”。没有生理或生化依据时，“超过某 θ 的时间份额”不能自动称为普适生长季。

其它需要限制的承诺：Held–Hou 的 Hadley 尺度不直接给出准确的整数 C5/C7 环流圈数；如记录环流体制，应说明它是模型配置、诊断还是经验标签。Hycean 通常指富氢大气下的水海，不能直接占用“液氢溶剂”码。编码能表达某世界、引擎能生成输入、分类判据已验证，是三个不同的支持等级。

### 3.1 恒温为何不使热量分类失效

原提案 §3.6/§5.2 在普通世界使用 A/C/D/E/F 热量类，在潮汐锁定世界改用 Ls/Lt/Ln 表示星下区、晨昏区与夜侧。这样同一字段从“有多冷、多热”变成了“位于何处”，破坏跨世界比较的语义。

全年每个分箱都是 15°C 时，均温、最低分箱均温、最高分箱均温都为 15°C，范围为 0°C。这些量全部有效；没有唯一“最热季”，因此温度季节相位不适用，不能由任意最大值索引指定夏季。按原提案的温度节点仍可归入 C 带，但最终分类采用哪个阈值集合需另行验证。

| 输入状态 | 应保留的表达 |
|---|---|
| 恒温、均匀降水 | 热量有效、温度范围为零、降水均匀、雨热相位不适用 |
| 恒温、周期降水 | 热量有效、保留降水集中度和形状、雨热相位不适用 |
| 温度和降水都有周期 | 信号足够、峰值可识别且采样充分时，才计算雨热相位 |

因此不能使用“温度振幅很小 → 强制 Pf（无显著湿季）”。无法识别温度相位，不等于没有降水季节性。

### 3.2 同一晨昏位置可以有不同温度

用三个假想地点说明语义：它们都位于晨昏区，温度分别为 −80°C、15°C、80°C。三个地点可以共享几何标签 `Lt`，但这个标签不能替代热量描述。这些数字是解释性反例，不是模型预测；具体温度取决于辐照、大气、云与热输送等条件。同一行星的晨昏线上也会因海拔与输送不同产生温差。

原提案的 45°–90° 分区是几何约定，不是普适宜居边界。建议独立记录温度与照明，示意如下（尚未实现的接口）：

```yaml
thermal:
  mean_K: 288.15
  min_K: 288.15
  max_K: 288.15
  seasonal_range_K: 0
illumination:
  regime: stellar_synchronous
  region: terminator
seasonality:
  temperature_phase: null
  temperature_phase_status: not_applicable
```

实际契约还需统计周期、分箱时长、锁定对象与主照明源；这里的极值是气候分箱平均值的极值，不是天气瞬时极值。几何可以只作为解释元数据，不必为“独立”立即增加必填编码段。

## 4. 推荐的最小数据与分类架构

### 4.1 序列契约：时间优先，不固定为 12 个等长“月”

输入明确 `bin_start/end` 或 `duration_seconds`，并区分温度平均值、降水平均通量和累计量。以 w_i=Δt_i/ΣΔt_i 计算温度平均；以 ΣP_iΔt_i 累计降水；PET/参考需求必须覆盖同一时段。

同时记录：变量是近地面气温还是地表温度、空间分辨率、统计起止时间、是否多年气候态、时间分辨率、数据来源与版本。不同物理量不能因都叫 temperature 就混用。

Earth 的月度气候态和 Nacrea 的轨道相位分箱可以接入同一契约。年均值从序列导出。用于气候分类的周期要声明；若光照、食和轨道周期不公度，不能假设一个短轨道周期就是完整气候重复周期。先允许更长统计窗口与多周期来源说明，不急于实现通用多频谱分类器。

“低于阈值的时间比例”用月均输入计算时，只表示**对应分箱平均温度低于阈值的时间份额**，不是实际霜冻天数。Nacrea 较长太阳日的日内极端可能被月度平均抹掉：若下游需要，新增日内统计或更高频输入，而不是由 UCC 猜测。

### 4.2 描述量：少而互补

| 描述组 | 首期建议保留 | 解释边界 |
|---|---|---|
| 温度 | 时长加权均值、分箱均值 min/max、max−min、指定阈值以下的时间份额与实际时长 | `max−min` 明称范围，避免与半振幅混淆；不是天气瞬时极值 |
| 降水规模 | 平均率、窗口总量、物质/单位 | “每本地年”总量不适合不加解释地跨世界比较 |
| 供需 | 同时段 AI=P_total/Eref_total、模型来源、有效性 | 描述参考气候需求，不是土壤湿度 |
| 季节供需错配 | Σmax(Eref_i−P_i,0)Δt_i / ΣEref_iΔt_i | 忽略储水和横向输水的同期亏缺诊断，不命名为实际干旱强度 |
| 季节形状 | 降水集中度；可选第一/第二谐波强度 | 集中不等于单峰，也不等于降水丰富 |
| 相位 | 可识别时的相对相位及质量标记 | 近恒定、多峰、欠采样时，不强行指定唯一峰值 |

固态降水比例对水文很有价值，宜作为后续可选描述量；有真实 rain/snow 输出时使用。仅凭月均 T 给出的比例必须标注为代理估计，不冒充实际降雪观测。

本轮试验采用一个集中度候选：

```text
w_i = Δt_i / 总时长
q_i = P_i Δt_i / 总降水量
C_TV = 0.5 Σ |q_i − w_i|
```

它表示降水在时间上的分布与均匀降水率的差别，有界、直观，也能处理不等长分箱；无降水时未定义。这是本评审提出的候选，不是声称复现 Knoben 或 Feng 的公式。它和熵类指标等应通过反例及敏感性比较后再选一个，首期不要全部加入产品。

第一/第二谐波只是候选形状诊断。双峰识别需要绝对信号强度、分辨率和重建误差检查，不能仅比较 H2>H1：均匀降水的两个浮点残差也可能满足该不等式。相对相位需另行定义统一的时间原点和相位约定，本轮脚本未实现最终相位算法。12 点采样也不能精确恢复任意六阶谐波相位；改变分箱数会影响峰值、极值和阈值时间份额，应检查收敛与边界敏感性。

### 4.3 分类：保留有限主轴，修饰语按需出现

建议主类只表达**温度背景 + 参考水分供需等级**；温度季节范围、供需错季、降水集中/双峰作为可选修饰语。所有连续描述量仍可查询。

这不是最终阈值表。第一轮应把少量候选阈值放入固定版本的试验 profile，比较其信息损失和可读性后再冻结。地球经验节点可以保留为候选，但不得标成跨世界物理定律。Earth/Nacrea 优先共用一个已声明条件的水循环 profile；不能为让每张地图“看起来合理”各自重新取分位数。

每个候选新增轴或例外必须回答：它避免哪一组已记录的误合并？有哪个下游用途？可否仅保留连续值？没有可重复证据就不添加。暂缓通用 DSL、`rebind`、混合溶剂自动分类和按世界自动调节字母含义。

“季风”含有环流机制含义。只有降水集中时显示“降水高度集中”；如确实需要季风标签，应由独立、明确的环流诊断支持。极少量降水的高度集中尤其不能被命名成湿润季风气候。

### 4.4 部分有效、海洋与不确定性

区分 `valid`、`missing_input`、`not_applicable`、`unsupported_model`、`insufficient_resolution`。恒温的热量统计有效，但温度季节相位不适用；缺 PET 不能让整条 UCC 记录消失。

P=0、Eref>0 时 AI=0；P=Eref=0 时 AI 未定义。P>0、Eref=0 应单列“无正参考需求”，不把无穷值偷偷塞入普通湿润档。接近零的需求需要模型与精度相关的判断，不能随意加 epsilon 获得看似稳定的类别。

海洋保留温度与季节描述；面向陆地的干湿类可不适用。`surface_type=ocean` 是元数据，不能替代所有气候字段。

不确定性至少分开：输入不确定、描述量不可识别、靠近分类阈值、模型适用性不足。跨 profile 比较或地图图例合并不得重写原始类别和描述量。暂不使用历史滞回修改分类，以免同一输入因执行历史不同产生不同结果。

原提案按低于 0.5% 等比例合并稀有类，可能抹去岛屿、高山或生态避难所。世界其它区域发生变化时，未改变气候的地点不能因此换基础类。稀有类合并只作用于图例，保存显示规则版本；不改底层科学字段。

## 5. Earth 与 Nacrea：同一套语义，分别验证输入能力

Nacrea 对 Aegis 同步，不是对 Ignis 同步。当前设定约 3.147 地球日自转/绕母星周期、约 3.25 地球日太阳日、约 100 地球日周年；详见 [共有物理评审](earth-nacrea-shared-physics-2026-09-17.md)。

| 同步对象 | 近乎固定的天空对象 | 恒星昼夜含义 |
|---|---|---|
| 行星对恒星同步 | 恒星 | 在低偏心率、低倾角等近似下，可有固定昼夜与晨昏区 |
| 卫星对母行星同步 | 母行星 | 恒星通常仍升落；仍有太阳昼夜 |

Nacrea 的向 Aegis 面/背 Aegis 面不是永久白昼面/黑夜面。母行星反射光、红外辐射和食增加强迫，但不会消除恒星昼夜。同步本身也不保证严格无季节：偏心率、倾角、天平动、食或多体照明都可能引入周期变化。固定星下点分区必须声明适用近似、参考纪元或统计定义。

因此建议：

1. 基础分类只看输入气候状态；世界名称、锁定布尔值和环流圈数不触发另一套温度定义。
2. 锁定对象、主要光源、太阳日、统计周期作为解释元数据。仅在满足条件时显示恒星固定昼夜几何标签。
3. 同样的降水率和参考需求率，在 100 日与 365.25 日窗口中应得到相同 AI，但累计量和阈值以下的实际时长不同，两者都要保留。
4. Nacrea 水分分类的可信度受参考需求模型限制。共用一个函数不等于完成物理迁移验证；不应为隐藏这种局限增设 Nacrea 专属阈值。
5. 将正常 Nacrea、修改年长、弱温度季节但强降水季节等固定序列纳入独立分类夹具，避免每次验证分类都必须完整生成世界。

现有实现仍有需先核清的输入问题：Hamon 使用固定 12 小时日长近似；降水预算中有 365.25 年尺度换算和 `/12`，PET 使用 `orbital_period_days/12`；月度温度还受到年值校正。365.25 可以作为合法参考时间单位，问题是必须区分每地球年的率与每当地年的累计量。在时间和通量契约核实前，不能把当前 Earth/Nacrea 输出当作 UCC 的科学真值。

代码入口：[climate_physics.py](../../src/dreamulator/engine/climate_physics.py) 的 `koppen_classify()` / `potential_evapotranspiration_hamon()`、[climate_simulator.py](../../src/dreamulator/map/climate_simulator.py) 的月度预算与 PET 消费链，以及 [月度解码](../../frontend/src/api/monthlyClimate.ts) / [显示 hook](../../frontend/src/viewers/map/useMonthlyClimate.ts) 中现有 12 bin 和相位约定。仅替换汽化潜热与摩尔质量也不足以实现跨压力/组分/重力的通用 PET，还需辐射供能、空气动力输送与饱和物性等闭合条件。

## 6. 是否需要更多测试例？需要，但要改变组织方式

“Earth、Titan、同步行星都能输出一个代码”只证明接口覆盖。应按会丢失的信息、应该保持的不变量和可能失败的假设建立测试矩阵。

### 6.1 成对反例：优先验证区别是否保留下来

| 对照输入 | 应保留的差异 / 不变量 | 验证层 |
|---|---|---|
| 相同均温，恒定温度 vs 冷暖交替 | 季节范围与低于阈值的时间份额不同 | 描述量 |
| 恒温 + 均匀降水 vs 恒温 + 季节降水 | 两者热量有效；后者仍有降水季节性 | 描述量/分类 |
| 相同年 P/PET，供需同步 vs 反季 | AI 相同，同期亏缺不同 | 描述量 |
| 相同降水总量，单峰 vs 对称双峰 | 不能只凭最湿月或第一谐波合并 | 形状诊断 |
| 极少量集中降水 vs 大量集中降水 | 相对集中度可相同，降水规模不同 | 标签语义 |
| 相同晨昏几何，寒冷/温和/炎热 | 温度轴不同；几何仅为共同标签 | 接口/分类 |
| 相同 T/P/需求，改世界名字或锁定对象元数据 | 基础描述量不变；几何说明可变 | 元数据隔离 |
| 相同气候强迫，有无地下水/冰川补给 | UCC 气候不变，实际水可用性允许不同 | 跨层契约 |
| 同温同雨的陆地与海洋 | 热量不消失；陆地干湿类适用性可变 | 部分支持 |
| 同一物理气候，不同历法原点、单位、分箱 | 不应仅因表示法变化换类 | 不变量 |
| 相同归一化年周期，100 日 vs 365.25 日 | 比例型量一致，累计量与绝对时长不同 | 跨世界时间 |
| 无降水、无需求、缺失数据、分辨率不足 | 分别输出正确有效状态 | 边界行为 |

这里的“保留差异”首先要求描述量能表达。**不要求每个反例对都强制得到不同主类**：离散分类必然压缩信息，关键是丢失哪些信息、是否影响约定用途、是否可由修饰量恢复。

### 6.2 五层验证，不能相互冒充

| 层级 | 数据与方法 | 验收意义 |
|---|---|---|
| L0 数学契约 | 手工序列、单位变换、历元平移、分箱拆分、非法输入 | 公式和状态含义正确 |
| L1 对抗案例与阈值 | 上表反例；各阈值的两侧/等值；小扰动与分辨率变化 | 不出现语义偷换，边界行为可解释 |
| L2 Earth 外部气候 | 站点/公开气候态，覆盖湿热、季风、地中海、沙漠、海洋性、大陆性、极地、高山和双峰雨区 | 与引擎误差脱钩，检查描述和分类的覆盖、稳定与信息损失 |
| L3 独立用途验证 | 有独立径流/积雪等观测的区域或流域；气候输入和响应分离 | 分类是否对声明用途有价值 |
| L4 跨世界压力测试 | Nacrea 固定夹具；已有理想化 GCM 输出中的同步、强季节、海洋和水受限案例 | 验证迁移语义与适用域；不能宣称外星实测验证 |

Earth 初期人工审阅可选择约 20–30 个代表地点，但这不是统计有效性的保证。正式比较需要更广的数据与空间留出；一个热带站点不能代表全部热带。阈值校准集、最终评估集要分开，避免邻近网格泄漏造成虚高性能。

流域径流验证要用流域气候汇总，而非把一个网格类别直接与整个流域响应对应。还需控制土壤、地形、水库、灌溉和人为取水等混杂，或至少分层报告。UCC 不负责解释全部径流差异。

对 Nacrea 没有观测真值时，验证应分成“公式/契约成立”“模型间一致性”“物理真实性未知”。ExoPlaSim 等输出可以提供有意义的压力测试，不能被视为无误差的裁判；无需为了推进 UCC 先建设自己的 GCM。

### 6.3 本轮已经执行的测试

[合成实验脚本](ucc-design-experiments-2026-09-17.py) 与 [结果 JSON](ucc-design-experiments-2026-09-17.json) 中，**26 项描述量语义检查通过**。

其中两个直观结果：

- 两个序列的总 P 与总需求均为 36，因此 AI 都为 1。供需同步的同期亏缺为 0；互相错季的同期亏缺为 2/3。年 AI 不足以解释季节缺水压力。
- 恒温 15°C 加上三段集中降水，温度范围仍为 0，温度相位未定义，但降水集中度候选为 0.75。不能因为没有温度季节就标记“降水全年均匀”。

脚本还验证了共同单位缩放、历元旋转、相同分箱的精确拆分、不等长分箱的均匀降水率、短年总量与 AI、零降水/零需求/缺 PET、单调性及对称双峰等。

**范围限制：这不是正式 UCC 实现，也没有测试最终类别阈值、实际几何判定、完整相位算法、数据集精度或 GCM。** “同几何不同温度”的用例只构造不同温度序列，验证描述量没有抹去温度差异。精确拆分不变量也不意味着粗化序列不会损失信息。

### 6.4 应当如何评估一个分类候选

不再使用“达到 Köppen 95% 一致率”作为验收线。改为同时报告：

1. **契约正确性**：规定的不变量与边界用例全部通过；不支持的情况不能伪装成有效类。
2. **压缩损失**：类内温度、冻融份额、供需错配、季节形状差异有多大；是否把目标用途的重要反例合并。
3. **稳定性**：输入不确定范围内换类比例、与阈值的距离、不同时间分辨率的结果差异。重点区分正常边界跳变和远离边界的不稳定。
4. **覆盖率**：已验证、未验证、不适用和缺失各占多少；不能靠大量 unknown 换取低错误率。
5. **独立用途效果**：留出数据中类内响应差异、类间区分度或预测误差，与简单基线比较。
6. **复杂度**：类别数、自由阈值数、例外数、解释成本和运行开销。

基线至少包括“均温 + 年 AI”的简单分组、Köppen（在 Earth 有意义的区域）、完整连续描述量。比较时控制类别数量/参数复杂度，或报告性能—复杂度曲线；不能用数百个 UCC 类战胜几十个 Köppen 类就宣称更优。通过消融比较“加季节范围”“加供需错配”“加双峰”各自的增益，决定哪些进入主类。

这些指标没有适用于所有用途的统一及格线。可先测量简单基线，预先写定允许的误差与复杂度预算，再在未参与调参的数据上评估。若只有可视化需求，先以解释清晰、关键反例覆盖和稳定性作为产品验收，不包装成独立生态验证。

## 7. 实施路线与停止条件

### 第一步：冻结语义，不冻结字母表

明确输入时间/通量/表面契约，整理固定夹具与适用状态，完成独立描述量计算。暂时只输出数值与解释，不承诺任意世界已支持。先核清现有 P/PET 时间基准。

**完成条件**：L0 通过；Earth/Nacrea 输入可追溯；恒温、缺需求等边界不会丢失其它有效字段。

### 第二步：比较少量分类候选

用同一批外部气候态比较有限的温度/供需分组，保留季节修饰量。Köppen 并列计算作为参照；记录分歧原因，不强行消除。按相同复杂度进行消融与扰动实验。

**完成条件**：能说明相对简单基线保留了哪些有用差异；没有靠世界专属补丁达成结果；阈值与有效域可固定成一个可复现版本。若收益不足，先发布描述量浏览，不继续堆规则。

### 第三步：验证实际用途，再扩展世界范围

选一个用途做独立验证，例如流域季节供需比较；同时完成 Nacrea 迁移夹具。实际证明需要时再增加固态降水、日内极端或其它诊断。甲烷与混合溶剂等待参考需求和物性模型具备可检验依据。

**新增复杂度的停止规则**：没有稳定的输入、可重复的失败例和明确用途，就不新增分类轴/例外；新增项若不能在留出测试中带来足以解释的收益，就保留为可选连续量或移除。

开发效率上，建议把“看地图哪里不像”改为“固定夹具报告 → 数据集摘要 → 地图定位”。地图仍用于发现空间异常，但每次发现都应落到输入错误、描述量错误、阈值问题或展示问题中的某一层。避免因一个地区颜色不合预期，就同时改模拟器和分类阈值。
