## 1. 概述

dreamulator 的地图系统采用**球面质心 Voronoi 镶嵌（Spherical CVT）**作为核心数据
结构：标准 20 万 cell（~51 km/cell），板块构造、地形合成、湖泊标记与气候模拟全部
直接在球面网格上完成，最终投影为 4096×2048 等距圆柱栅格用于渲染与外部交换。

地形生成**没有独立的 `map` 命令**——它由 `dreamulator build` 的 geological 层统一
驱动（`terrain_config.yaml` + `geography.yaml` 配置），管线内部按固定顺序执行 8 个
相位，依次是 CVT 网格、板块、构造演化、边界、地形、气候、极地冰盖和导出。`dreamulator build`
默认跳过管线内的气候相位，气候由 climate 层的引擎单独构建。每个相位按输入内容指纹
缓存，改动只重跑受影响的部分。全量构建（200k，含 climate 层）基线
~391 s（v0.36.0 口径；性能剖析见 [design/profiling.md](../design/profiling.md)）。

各相位的算法原理（Cortial 2019 板块演化、边界效应地形、fBm、海陆判定、封闭盆地
湖泊）见 [geological-pipeline.md](../design/pipelines/geological-pipeline.md)。

## 2. 快速开始

### 2.1 CLI 生成（标准路径）

```bash
# 初始化世界（模板自带合理默认配置）
uv run dreamulator init myworld --template earthlike

# 构建：按层级 DAG 顺序执行，geological 层内跑地形管线（默认跳过气候相位，由 climate 层构建）
uv run dreamulator build myworld

# 强制全量重建（跳过指纹缓存）
uv run dreamulator build myworld --force
```

构建进度按相位实时显示（`1/8 CVT Mesh` … `8/8 Export`），完成后所有数据文件写入
行星的地图目录（见[第 6 节](#6-数据存储)）。

### 2.2 API 生成（自动化/前端）

后端运行时（`dreamulator serve`）可通过 REST 端点触发生成：

```bash
curl -X POST "http://localhost:8000/api/worlds/myworld/maps/planet_x/generate"
```

端点的完整参数与响应见自动生成的 OpenAPI 交互文档（serve 后访问
`http://localhost:8000/docs`）。前端地图查看器顶栏的生成按钮走同一端点。

### 2.3 查看结果

```bash
uv run dreamulator serve --open
```

浏览器自动打开 → 进入目标世界 → 选择行星 → 地图查看器（2D）或球面查看器（3D）。
操作见[第 4 节](#4-在查看器中查看)。

## 3. 配置参数

地图生成的配置文件是 `layers/geological/input/terrain_config.yaml`（分支中可覆盖），
完整字段表见 [geological-pipeline.md](../design/pipelines/geological-pipeline.md) 与
`TerrainPipelineConfig`（`src/dreamulator/map/pipeline_types.py`，字段注释即文档）。
海陆分布的「创意设定」不在此文件——用 `geography.yaml` 地理锚定（大陆锚点 + 陆地
偏置场，见 [design_patterns.md](../worldbuilding/design_patterns.md) 模式 9）。

**常用参数速查**（真实字段名；默认值取自 `pipeline_types.py`）：

| 参数 | 默认 | 说明 |
|------|------|------|
| `seed` | 42 | 随机种子——相同种子 + 相同配置 = 相同结果 |
| `num_nodes` | 100,000 | CVT 网格节点数（现行标准 200k） |
| `num_plates` | 20 | 构造板块数量 |
| `sea_level_auto` | true | 按目标陆地比例自动校准海平面 |
| `sea_level_offset_m` | 0 | 海平面偏移（auto 关闭时的手动海平面） |
| `convergent_uplift_m` | 4000 | 汇聚边界（造山带）基准抬升 |
| `divergent_depth_m` | 2000 | 张裂边界（裂谷/洋脊）基准深度 |
| `noise_octaves` / `noise_persistence` / `noise_lacunarity` | 6 / 0.5 / 2.0 | fBm 噪声三层参数 |
| `regional_noise_scale` | 0.5 | 大尺度区域噪声（大陆内部起伏） |
| `export_width` / `export_height` | 4096 / 2048 | 栅格导出分辨率 |

**气候参数不在地形配置里**：温度/降水由气候引擎从恒星强迫（光度/轨道/倾角/温室）
第一性推导，调气候请改 `stellar.yaml` / `planets.yaml` 或 climate 小节的物理旋钮
（见 [climate-pipeline.md](../design/pipelines/climate-pipeline.md) §13 常数表）。

## 4. 在查看器中查看

### 4.1 启动与导航

```bash
uv run dreamulator serve --open      # 后端 + 前端，默认 http://localhost:8000
```

进入世界 → 行星 → 地图查看器。**导航**：按住鼠标左键拖拽平移、滚轮缩放、移动鼠标
查看底栏属性、单击选中单元格。

### 4.2 图层面板

图层按渲染语义分四个**槽位**（slot），合成顺序固定为底图 → 专题 → 填充 → 特征；
UI 按学科组织为五个面板组（**地形 / 气候 / 生态 / 文明 / 开发**，开发组为诊断偏差层，
仅 Earth + 开发者模式显示）：

| 槽位 | 选择方式 | 包含图层（示例） |
|------|---------|-----------------|
| **底图** | radio（恰好 1 个） | 地形（默认）、海陆 |
| **专题着色** | radio（0 或 1 个） | Köppen、温度、降水、气压、Whittaker 群系、NPP、宜居/农业、诊断偏差热力层 |
| **分类填充** | 多选叠加 | 板块 |
| **特征标注** | 多选叠加（永远置顶） | 地壳边界、洋流、风场、海岸线、风/洋流偏差箭头 |

「主图层」用于选择地形、温度或其他专题着色。一次只激活一个专题图层，避免两套全表面着色混在一起。「叠加图层」可以同时开启海岸线、板块和风场等图层，并分别调整透明度。

右侧检查栏顶部可在「年均」和「月度」之间切换。选中的图层有逐月数据时，柱形图显示它的月度平均值。点击一根柱形会切换到对应月份。没有逐月数据的图层不显示柱形图。窄屏可从地图下方的「单元格与统计」打开时间控件。

全球平面和球面地图同时有原始高程图和计算网格时，可以在「地图工具」中的「地形来源」切换底图。导入高度图的世界默认显示原图，真实地球主世界及继承同一地形的分支默认显示 4096 × 2048 的 ETOPO1 高程。「计算网格」用于核对引擎使用的格点高程。切换底图不会改变专题图层的降尺度设置，也不会改变区域细化的输入。

在左侧「主图层」中，可以用「模式网格」查看原始结果，或用「降尺度」查看支持的气候图层。模型生成的柯本分类需要同一结果的完整逐月温度和降水，才能根据插值后的气候场重新分类。降尺度只影响地图显示，不会改变正式气候结果、叠加图层或右栏的网格读数。

真实地球等使用观测分类的地图默认显示「观测网格」，不会拿其他来源的月度温度和降水重算类别。发布包包含同版原始分类时，可以切换到「高分辨率观测」。此时地图直接显示原始分类，不在类别之间插值；右栏单元格和统计仍按观测网格读取。

南极和里海在两种视图中的颜色可能不同，分别见[南极的冰盖分类](../design/pipelines/earth-real-data.md#南极的柯本分类为何随显示模式变化)和[里海的水体掩膜](../design/pipelines/earth-real-data.md#里海为何会显示陆地柯本类别)。

「叠加图层」顶部的「粒子流」开关把风场/洋流从箭头切换为沿流场平流的粒子拖尾
（nullschool 式）。风场粒子按风速着色（蓝=慢 → 红=快），洋流粒子按暖/寒着色
（品红=暖 · 青绿=寒）；粒子透明度仍由对应图层的滑块控制。风场在月度模式下
跟随所选月份，洋流目前使用年均流场（月度洋流尚未进入数据契约）。关闭开关即
恢复箭头显示；偏差诊断箭头不受影响。

> 地形配色采用 NOAA ETOPO1 + ESRI Natural Earth 混合 hypsometric tint 方案，自适应
> 行星高程范围。各图层纹理按数据变化烘焙并缓存；拖动透明度仅更新 GPU uniform，
> 不触发重烘。

### 4.3 投影与昼夜

2D 地图使用**等距圆柱**（Plate Carrée）单一投影——与引擎栅格数据同构，
2:1 矩形、水平环绕、经纬线正交，GPU 渲染。极区形状/面积的真实比例请切
3D 球面视图查看（等距圆柱在极地附近有水平拉伸）。

**2D 昼夜光照**：URL 参数 `?sun=<经度>`（太阳直射经度）、`?season=<角度>`（0=春分…
驱动赤纬）、`?night=1`（开启昼夜叠加）；与 3D 视图经 URL 同步、可分享。左侧「光照」中的「季节（仅光照）」不会改变右栏的数据月份。

**纯净视图（视频录制）**：顶栏 ⛶ 按钮或 URL 参数 `?clean=1` 进入——隐藏全部界面
与场景装饰（顶栏/左右面板/状态栏/经纬网/极轴/小地图），只留地图或球体画面与
箭头图层；球面为直角满幅、鼠标悬停不再产生蓝色高亮。按 Esc 或悬停右上角的
退出按钮退出；2D/3D 通用，切换视图后保持。

**自动旋转（3D，视频录制）**：顶栏 ↻ 按钮或 URL 参数 `?spin=1` 开启——球面
慢速匀速自转（约 120 秒/圈）。拖拽或按 N（北极回位）期间自动暂停，松手后
恢复。与纯净视图组合 `?clean=1&spin=1` 即标准录制姿态。

**粒子流与月度链接**：`?particles=1` 开启粒子流显示；`?monthly=1` 切入月度模式，
用 `?month=<索引>` 指定模型数据窗口（索引从 0 开始；地球样例的 0 表示三月）。用 `?detail=downscaled` 保留降尺度显示。粒子拖尾是屏幕空间轨迹：相机旋转或地图平移时
旧拖尾会清空，但粒子本身仍按流场方向显示为短轨迹（至少约 5 像素）；视图静止后
重新积累长拖尾，既不会拖出残影，也不会让粒子在拖动时消失。

**图层深链**：URL 参数 `?layer=<图层id>`（如 `temperature`、`precipitation`、
`koppen`）——打开链接时该图层按默认不透明度点亮，语义与在图层面板里点击一致
（仅同槽互斥，地形底图默认保留）。切换主图层时 URL 自动跟随（`replace` 方式，
不产生浏览器历史记录），复制地址栏即可分享当前图层；默认地形底不写入参数，
保持链接干净。

### 4.4 单元格详情（右面板）

**未选中时 — 行星摘要**：行星名 + seed、海陆比例、高程范围、板块数、网格节点数。

**悬停/选中时 — 单元格属性**（按学科分组）：

| 属性 | 说明 |
|------|------|
| 经度 / 纬度 | 地理坐标（度） |
| 海拔 | 米 |
| 地壳类型 | oceanic / continental / transitional |
| 板块 / 边界类型 | 所属板块 ID；convergent / divergent / transform / 无 |
| 汇聚速率 / 距边界距离 | cm/yr；km |
| 气候 | 温度、降水、Köppen 分类（+ 月度极值） |
| 面积 | km² |

### 4.5 性能

地图查看器使用 KD-tree 数学命中测试替代 SVG polygon hit-test：hover 延迟 ~5ms
（O(log n) 查找）、DOM 仅 1-2 个高亮 polygon、rAF 节流。cvt-mesh 端点默认
MessagePack 传输（200k cell 网格 ~31.6 MB gzip，前端透明解压）。

### 4.6 选取区域、浏览并下载高程图

在平面图或球面图打开「区域选取」。可以输入中心经纬度，也可以选中一个地图单元格，再点击「用选中的地点」。在桌面平面图上，按住 Ctrl 或 Command 键单击即可选中单元格。边长以千米为单位。点击「移动到选区」，视角会对准选区中心，带深色描边的白色虚线会标出边界。如果拖动地图离开了选区，再点击一次即可回到中心，不必修改经纬度。中心和边长也会写入网址，因此刷新或切换平面图和球面图时，视角会对准同一选区。单元格高亮仍可单独使用。点击「清除选区」会移除边界和网址中的选区，不会删除地图。

点击「移动到选区」后，再点击「查看区域」。即使还没有区域地图，本机版与静态站也能从全球高程预览该区域。预览使用和选区轮廓相同的方位等距投影。本机版列出同一选区的本机成果，静态站列出当前浏览器保存的成果。「返回全球选区」会回到进入区域前的平面图或球面图，并对准原选区中心。

在球面图网址的查询参数中加入 `zoomPreview=1`，即可试用选区的连续缩放。「拉近选区」和「拉远至整球」在同一球面视图内移动相机，不改变选区也不生成新地形。面板显示相机距基准球面的高度，不是距实际地形的高度。

在静态站的区域地图生成细化结果后，先保存到该世界，再返回球面图。选中地形图层并拉近同一选区时，球面会显示该选区最近保存的细化结果。拉远、移出选区或没有可读的细化结果时，仍显示全球底图。高清结果只替换选区内的地形纹理，不会改变球面高度，也不会替换气候图层或检查器中的全球网格数据。

在区域地图页展开「导出高程图」，选择分辨率和文件格式后点击下载。分辨率只改变下载文件的像素数，不改变底图或视图缩放；增密仅做插值，不会增加地形细节。两种格式都从数值高程生成，不是地图截图。

- 默认的 **16 位灰度 PNG** 将本次输出的最低高程映射为黑、最高高程映射为白。不同区域的同一灰度不一定代表同一高程。PNG 的 `Description` 文本字段以 JSON 保存 `min_m` 和 `max_m`；用 `min_m + 灰度值 / 65535 × (max_m − min_m)` 可还原至量化后的米值。高程处处相同时，图像为中灰，两个端点都记录同一高程。
- **32 位浮点 TIFF** 的像素直接储存以米为单位的高程，适合数值处理。普通看图软件可能无法正确显示其灰度层次。TIFF 不包含 GeoTIFF 坐标标签。

两种格式均在图像描述中记录来源、投影和范围。已有区域地图默认下载其地形底图所用的数值高程并保留原尺寸；导出面板会标明这是输入高程还是已有处理结果。需要成套的气候图层或更多细化方式时，可以使用[区域数据包命令](cli.md#区域数据包region-pack)。

「区域选取」面板内的问号和区域地图页面右侧的问号会在新标签页打开对应的详细帮助。鼠标悬停在输入框、按钮和底图等控件上，可以查看每项操作的说明。

区域地图与全球平面图使用相同的工作台布局。默认显示从全球高程图截取的原始地形。本机站和静态站都可用地图顶部的「区域数据来源」切换到同一选区的可用成果。静态站会列出本次细化和此浏览器已保存的成果。切换不会重新计算或改写全球地图。左侧「图层」提供可用底图、地形对照与叠加开关，右侧默认显示点位详情。点击左下角的「细化地形」，可在右侧查看设备、设置、进度和导出选项。不能从当前成果再次细化时，左下角显示「高程与导出」。窄屏可从顶部打开图层抽屉，点按地图后在下方查看详情。

「地图高程」是独立的图层，可对照原始高程与细化结果。主图层顶部的「区域源数据」和「TD 条件网格」统一切换 Terrain Diffusion（TD）使用的五个条件：高程、年均气温、月均气温标准差、年降水和月降水变异系数。两者不影响地图高程和水文。年均气温在源数据中是地表值，在条件网格中折算至海平面。没有可核验数据的图层置灰；缺少条件网格的旧成果不从当前世界补算。对于已发布的世界，浏览器使用当前分支的正式高程和气候。如果没有配套气候，面板会标明只使用高程；读取失败时可重试。浏览器保存成果时记录实际使用的条件网格，重开后可查各层的尺寸、单位和点位数值。重采样不等于降尺度。

使用鼠标滚轮或触屏双指捏合可缩放地图。在选区内悬停可查看点位数据，双击锁定位置，触屏上点按即可。右侧始终展开经纬度，并自动展开当前主图层对应的信息，其余分组可以手动打开。

有全球底图时，虚线标明选区边界。框外只显示全球地形作为参照，经纬网跨过虚线，区域河网只覆盖实际计算范围。框外数据不参与点位查询、细化或导出。可用「查看选区与周边」恢复取景；无全球来源时，可用「全图」和「铺满」。切换图层不改变视角，取景也不会改变导出的区域范围、投影或像素尺寸。

区域地图的「计算设备」在两种部署模式下位置相同。本机版显示 TD 运行环境选用的设备，例如「本地连接 · NVIDIA L20」；静态站显示浏览器选中的设备，例如「WebGPU 连接 · NVIDIA」。如果浏览器只报告厂商和架构，页面不推测具体型号。设备状态不代表当前选区已具备细化所需的输入或内存。

#### 本机网页细化

本机网页支持重绘、混合细化和只计算水文。重绘根据输入的高程和气候生成新地形；混合细化使用填写的原生间距划分地形尺度，在原图小尺度上加入模型生成的起伏。两者都在生成的高程上计算河流和湖泊。选择「只计算水文」时，直接使用原图作为水文计算的输入。这个入口要求 Linux 和至少 16 GiB 可用内存。重绘与混合还需要为[命令行细化链](cli.md#区域构建region-build)配置 TD 模型和运行环境，再在启动本机站时指定该目录：

```bash
DREAMULATOR_TD_DIR=/path/to/terrain-diffusion uv run dreamulator serve
```

打开已有月度气候结果的全球选区，或包含细化输入的方形区域地图。点击左下角的「细化地形」并展开「生成细化地形」，确认范围和网格数量后开始。当前上限是 550 km 边长和 1024 × 1024 输入网格，输出的长宽各是输入的两倍。所选像素数是交付栅格的密度，不是原图或模型的有效精度。本机网站一次运行一个构建或细化任务。页面显示准备、生成地形、计算水文和保存结果等阶段。保存开始前可以取消；刷新页面会重新连接当前任务，不会再次启动计算。

本机网页和命令行使用相同的 `region pack` 与 `region build`。构建过的世界如果保留了导入的全球高程图，就从原图裁取选区；没有导入源的世界从计算网格取高程。气候和径流仍来自这个世界的构建结果，放大栅格不会产生新的气候精度。模型的地形条件会按原图与计算网格的海拔差调整温度，但不会据此生成新的局地降水。

混合细化的「原生间距」留空时取数据来源的尺度，例如地球的 4096 × 2048 原图约为 9.77 km。「混合尺度」留空时取原生间距的四倍。三种本机方式都可以在「高级参数」里调整「河道起始阈值」。数值越小，画出的支流越多；留空则按网格自动设定。这些设置分别对应 `region build` 的 `--native-resolution-km`、`--preserve-wavelength-km` 和 `--river-threshold`。

任务完成后点击「对照并下载结果」。在地形底图中切换原始高程和生成结果，地图的位置及缩放不变；点击同一地点可以读取两份数值。下载面板使用当前显示的地形来源，默认保留该来源的像素尺寸。细化结果另存为一份区域地图，不改写原始世界或原区域地图。

#### 静态站的浏览器细化

在已发布的全球地图上选取边长 45–184 km 的方形区域，进入「区域地图」，展开「生成细化地形（浏览器实验）」。「原生间距」指原始高程数据中相邻两格在地面上相隔多远。原数据每隔 360 米有一个高程值，就填 `0.36` km；每隔 50 公里有一个高程值，即使图片后来放大过，也仍填 `50` km。不知道就留空，直接选择处理方式。输入框和选择框都有悬停帮助。

保留了导入尺寸的全球图会自动填入相邻两行的距离，例如地球半径下的 4096 × 2048 图约为 9.77 km。东西方向的间距会随纬度升高而缩短。如果原图事先放大过，请按放大前的间距修正。未记录原生尺度的结果可留空。

- 「按输入场重绘」根据原图的大致地势生成山脊和谷地。「重绘并增强细节」可以调大模型细节的振幅，默认为普通重绘的两倍。两种重绘方式都可能改变山谷和海岸。
- 「混合细化」在陆地叠入模型的小尺度起伏，沿用原图的海陆范围和海底高程。请填写大于输出像素间距的原生间距。「混合尺度」决定从多大的地形起伏开始混入模型细节。留空时取原生间距的四倍，例如原生间距为 `0.36` km 时，约 `1.44` km 以下的起伏会逐渐混入细节。

想换一套随机地形，可以在「高级参数」里改随机种子。只想下载输入时，展开下方的「原始高程图」。

三种细化方式共用同一份约 1.14 GB 的模型。远程站点需要 HTTPS 和支持硬件 WebGPU 的浏览器；设备不支持时仍可浏览地图或下载原始高程。

「运行前计算预算」列出原图的南北像素间距、模型输入、预计输出和各阶段的分块数。初次试跑时，可以返回全球地图，选一个较小的区域来缩短计算时间。不同大小的选区使用同一份模型，三个阶段各有自己的分块数和每块耗时。也可以点击区域地图右上角的问号，在网页帮助里查看操作建议。

进度区域区分站点下载、读取本地模型缓存、文件校验、缓存写入、WebGPU 初始化和分块计算，并记录当前步骤和全程的耗时。已校验的模型按校验值保存在当前浏览器的站点存储中。刷新后在同一站点重跑时，可以复用这些模型，不必再次下载。如果站点存储不可用、空间不足，或者浏览器已经清理了这份数据，细化仍可从站点读取模型。支持后台线程 WebGPU 的浏览器会在那里初始化和运行模型，以便等待时仍可操作页面。

浏览器不提供初始化的百分比。开始计算后，页面显示当前块和已完成块数。生成粗地形时还会区分准备推理输入、等待推理返回和应用结果，并显示当前调用已经等待多久。首块前两次推理的调用耗时在结果页保留，便于比较首步和后续推理。一次调用可能包含显卡程序编译、计算和结果传输，这些工作在调用等待期间没有各自的进度。运行时建议让标签页保持可见，切到后台或设备休眠时，浏览器可能减慢或暂停计算。刷新或关闭页面会结束本次计算，已经保存在站点存储中的模型可以在重跑时复用。

等待时可以取消。浏览器在后台线程运行模型时，取消会停止该线程，不必等当前推理返回；否则要等正在执行的操作返回。失败提示会保留出错的步骤。后台线程收到显卡设备丢失通知时，页面会结束本次任务并单独提示，已有结果不受影响。

展开细化面板下方的「模型管理」，可以查看当前浏览器为模型缓存保存了多少数据，包括未清理的旧版本。若要释放空间，等当前细化结束后点击「清理模型缓存」。确认后会删除模型文件，保留地图、当前结果和站点设置。下次细化需要重新下载模型。

结果直接显示在地图上，可在同一位置切换原图与细化高程。下载默认使用 16 位灰度 PNG，也可选择以米为单位的 32 位浮点 TIFF。两种格式均保留细化结果的像素尺寸，并记录本次使用的处理方式、随机种子、原生间距和适用的细化参数。浏览器使用选区的高程，以及该分支已发布的配套气候；需要河流和湖泊时请使用本机网页或命令行。离开前请将结果保存到当前世界或下载。

发布者可用 Terrain Diffusion 的 Python 环境运行 `scripts/release/export_td_web_models.py <本地 90 m 权重快照> <新的输出目录>`。该环境须安装 `onnx`；导出完成后会输出清单的 SHA-256。把清单及三份模型文件设为可下载的静态资源，在构建前设置 `VITE_TD_MODEL_URL` 和 `VITE_TD_MODEL_SHA256`。前者使用 HTTPS 目录或相对于站点根目录的路径，后者填写导出脚本给出的值。GitHub Pages 工作流从同名仓库变量读取两项设置。跨域资源服务器须允许网页读取这些文件；模型默认不打包进站点。

当前模型合计约 1.14 GB，超过 [GitHub Pages 所发布站点的 1 GB 上限](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)。工作流从 `worlds-data` 发布包提取所需文件，浏览器读取导出后的网页数据，不直接读取发布包。模型可单独托管在支持跨域读取的对象存储；如果用 [GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases#storage-and-bandwidth-quotas) 供用户下载，单个附件须小于 2 GiB。将 Release 用作网页的自动下载源之前，要验证浏览器能读取重定向后的附件响应。更换托管可以改善首次下载时的速度和可达性；同一站点的后续运行仍使用浏览器里已经校验的缓存。

本机用 `npm --prefix frontend run build:static:local` 构建，再用 `npm --prefix frontend run preview:static` 在 `8026` 端口预览。需要从另一台机器代理访问时，可在预览命令后加 `-- --host 0.0.0.0`，并通过支持 WebGPU 的 HTTPS 代理打开。

#### 静态站的世界数据与备份

从世界页进入「世界数据」，可以查看浏览器占用、打开已保存的气候和区域成果、导出备份或删除浏览器数据。全球高程从「新建世界」导入，不在数据页上传。从全球地图完成区域细化后，点击「保存到当前世界」，原始选区和结果会一起保存，并保留来源天体及气候信息。

在「世界数据」列表中点击原图或细化成果，会直接打开区域地图。区域地图会读取此浏览器保存的高程，不需要重新细化；打开成果后，可以对照原图、展开「处理参数」或单独下载细化高程。「返回世界数据」可以回到列表。如果原图仍被某个结果使用，先删除该结果再删除原图。每个世界最多保存 128 项资料和成果，数据合计不超过 256 MiB。浏览器存储不足时，仍可单独下载已生成的高程。

用「导出世界数据包」生成 `.tar` 备份。在另一台设备打开世界列表，选择「导入世界数据包」，即可查看保存的结果，无须下载模型。浏览器世界可作为独立世界打开，已发布世界的新增资料会并入相同世界的浏览器数据，发布的底图保持原样。导入也接受 `.dreamulator` 备份，并将其作为浏览器世界打开。在世界列表的「浏览器中的世界」下，可以删除不再需要的自建世界，不会影响已导出的文件或发布数据。清理模型缓存不影响世界数据；清除整个站点数据前，请先导出要保留的世界数据。

在本机继续构建浏览器自建世界时，从数据包提取 `creation.tar.gz`，再用 `dreamulator snapshot restore` 恢复原始高程和世界设定。如需在本机打开区域地图，把数据包中 `packs/` 下的区域目录放到对应世界，保留本机的 `world.yaml` 和其他数据。浏览器试算在静态站恢复为试算结果，不会自动转成本机正式构建层。

如果需要备份本机服务已经构建的气候、其他图层和保存在世界目录内的区域成果，请在本机世界页的「世界构建」下选择「下载世界备份」。这种完整世界备份需要在本机用[命令行恢复](cli.md#完整世界快照)，静态站的世界列表只导入浏览器数据包及创建快照。

## 5. 迭代与分支

### 从高度图走到完整世界备份

如果是第一次操作，可以在首页选择「开始教程」。教程会指向以下步骤使用的真实控件；没有自己的高度图时，可以载入地球示例。选「跳过本条提示」可先收起提示，完成当前操作后教程会继续；也可随时退出，并从帮助页重开。刷新同一个标签页会保留教程步骤，但尚未保存的高度图和试算仍遵循各页面原有的保存规则。

1. 在本机网页选择「新建世界」和「从全球高度图开始」。可以上传自己的高程图，也可以使用地球示例。确认纯黑、纯白及海平面对应的高程。保存后在「世界参数」确认计算网格，默认是 18,432 个球面单元，再点击「构建」。
2. 构建完成后打开地图，在正式模式查看气候图层及其年均和月度变化。打开「参数实验台」，按天文与气候分组修改轴倾角、自转周期、邦德反照率或温室增温。保存到当前分支，或在「创建新分支」里填写名称后「另存为分支」。保存后顶栏的构建计划显示待重算层，点「前往构建计划」发起构建；实验台本身不运行计算。
3. 在新分支选取区域并打开区域地图。参照[本机网页细化](#本机网页细化)，确认选区输入和细化方式后开始计算。成功后区域数据包自动保存到世界目录，可从区域列表再次打开。
4. 回到世界概览，在构建区选择「下载世界备份」。完整备份包括原始高度图、正式输入、已构建图层、分支和保存在该世界内的区域成果，可用[命令行恢复](cli.md#完整世界快照)。

静态站创建高度图世界后，从世界列表或世界标题旁的「地图」进入全球工作台。在「气候实验台」点击「运行气候」，浏览器会用该世界的原始高程和网格设置运行完整 EBM，最多支持 20,000 个单元。点击「保存试算结果」，再打开这份结果并选取区域。已配置模型且设备支持 WebGPU 时，可以使用这份试算的气候条件细化并保存。最后在「世界数据」导出备份，备份包含原始高程、世界设定以及已保存的气候和区域成果。静态站不执行完整世界构建，也不写正式气候分支。

### 5.1 种子与参数迭代

```bash
# 换种子（在 terrain_config.yaml 改 seed 后重建）
uv run dreamulator build myworld --force
```

> 即使种子不变，修改任何参数也会改变地形——管线各阶段的输入变了。种子只保证
> 「相同配置 = 相同结果」。参数效果速查见[第 3 节](#3-配置参数)与
> [terrain_tuning_guide.md](../worldbuilding/terrain_tuning_guide.md)（海拔诊断链
> 与噪声换算）。

增量重建无需 `--force`：子阶段缓存按输入内容指纹自动失效（例如只改 `geography.yaml`
只重跑地理锚定之后的相位）。

### 5.2 分支工作流

分支系统允许在同一世界的不同地质方案之间并行探索，不覆盖主线：

```bash
# 在 geological 层分叉
uv run dreamulator branch create myworld pangea --at geological

# 分支上改 terrain_config.yaml / geography.yaml 后构建
uv run dreamulator build myworld --branch pangea

uv run dreamulator serve --open
```

打开地图后，可以在页面顶部用「分支」切换并比较结果。切换时会保留地图视图，但不会载入另一分支的试算或细化成果。

**典型分支策略**：

| 分支场景 | 分叉层 | 配置差异 |
|----------|--------|---------|
| 盘古大陆 | geological | geography.yaml 大陆锚点合并 + 低海平面 |
| 冰河时期 | climate | 行星物理（温室/倾角）调整，地质不动 |
| 海洋世界 | geological | 高海平面（目标陆地比例下调） |

### 5.3 控制海陆分布（替代「手动板块」）

板块分布由管线自动生成，**手动指定板块的机制是 `geography.yaml` 地理锚定**——大陆
锚点（位置/半径/强度）+ 陆地偏置场控制哪里该是陆，板块剖分在其上叠加地壳类型与
运动学。写法见 [design_patterns.md](../worldbuilding/design_patterns.md) 模式 9 与
[map_design_guide.md](../worldbuilding/map_design_guide.md)；「形状手绘、地貌物理
补全」的路线见[第 7 节](#7-导入外部高度图)的锚定灰度图。

## 6. 数据存储

### 目录结构（`map/manager.py` 的规范路径）

```
<world>/maps/<planet_id>/              # 主世界地图
├── map.yaml                # MapMetadata（CVT 参数、生成时间、投影、导入溯源）
├── cvt_mesh.msgpack.gz     # CVT 网格（gzip 帧 MessagePack，主要数据：cell 坐标、邻居与属性）
├── elevation.png           # 16-bit 等距圆柱高度图（渲染 + 外部交换）
├── plates.json             # 板块定义（名称、类型、cell 列表、欧拉极）
├── temperature.png / precipitation.png / koppen.json / climate_metadata.json
├── climate_monthly.msgpack # N×12 月度场（温度/降水/气压/风）
└── registry.yaml           # 图层依赖追踪（标记哪些下游层需要重算）

<world>/branches/<name>/maps/<planet_id>/    # 分支地图（覆盖主地图，缺省沿继承链向上取）
```

> `layers/geological/` 下的旧地图路径仅作向后兼容 fallback，新数据一律写顶层
> `maps/`。

### 产物管理（重要）

`maps/` 与 `layers/*/derived/` 是「input + 代码 + seed」的**确定性构建产物，不入
git、不走 LFS**（`.gitignore` 已忽略）。发版由
`uv run python scripts/release/publish_world_data.py` 一条命令完成构建 + 打包 +
上传（GitHub Releases 的 `worlds-data` tag），GitHub Pages 从 release 做静态导出。

### 文件大小参考（200k cell，nacrea 实测）

| 文件 | 典型大小 |
|------|----------|
| `cvt_mesh.msgpack.gz` | ~32 MB |
| `climate_monthly.msgpack` | ~23 MB |
| `koppen.json` | ~4 MB |
| `plates.json` | ~3 MB |
| `elevation.png`（4096×2048 16-bit） | ~3 MB |

## 7. 导入外部高度图

首页的 **导入我的地图**（地址 `/import`）和地图查看器顶栏的 **⬆ 导入高度图** 按钮打开同一个导入面板，两者都只在
API 模式提供。面板接受 8 位或 16 位 PNG、16 位 TIFF、32 位浮点 TIFF 和 JPG（自动识别）。JPG 是 8 位有损格式，
通常来自聊天软件的自动转换，导入报告会写明它的精度损失和压缩痕迹。作者先选文件，再选择灰度的含义并填写
数值，面板随即向后端请求只读预览，显示换算后的高程、海岸线、鼠标所指位置的高度和导入报告；确认之前不写任何文件。
如果按当前映射全图都会判成海洋或陆地，或者源图只用了一部分灰度，导入报告会说明原因并给出可以照着填的数字：例如最亮像素
现在折算多少米、把纯白高程调到多少米才能让它达到声明的高度，或者海平面阈值应设在哪个灰度级。这些只是建议，映射仍由作者
决定，导入不会自动修改。
从首页导入时可以新建世界（按模板创建，导入失败时删除刚建的世界），也可以选择已有世界或从地质层分叉的分支。
确认后按原图尺寸保存换算后的 `elevation.png`，随后进入地图页。平面图和球面图默认显示导入高程，可在顶栏切换为灰度图，
构建后也可切换到「计算网格」来检查引擎使用的高程。区域预览和原始高程图下载始终从全球高程栅格截取，不受这个开关影响。
如果保存的地图尺寸小于导入文件，需要重新导入原始文件才能恢复完整显示分辨率。首页会记住最近打开的世界，刷新后可以从
「继续上次的世界」回到原来的地图。

- 灰度怎样换算成米，由导入时给出的映射决定（`import-elevation` 端点的表单字段）。
  带水深的高度图用 `range` 模式，给出纯黑与纯白各对应多少米；只画了陆地的灰度图用
  `threshold` 模式，给出海平面阈值（8 位或 16 位图直接填整数灰度级，例如灰度 20 就填 20；
  浮点图填满刻度的比例，界面会按源图位深换算）、纯白对应的高度，以及要假设的海底深度
  （图里没有水深，所有海格都取这个值）；值本身就是米
  的浮点 TIFF 用 `metres` 模式。不给映射时按地图现有的刻度当作 `range` 读。三种模式的
  精确定义见[地图系统](../design/pipelines/map-system.md)的「高程语义与导入契约」一节。
- 预览和导入结果都会报告陆地占比、一级灰度对应多少米和海底是否为假设值。陆地占比分两种：「陆地占行星表面」
  按每行的球面面积加权，「陆地占图像像素」是等距圆柱图的
  像素比例，后者会高估高纬陆地。8 位图只有 256 级，陆地部分每级可能有几十米，能用 16 位就用 16 位。
- 网页只接收覆盖整个行星的 2:1 等距圆柱高度图，最大为 4096 × 2048 像素，文件不超过 64 MiB。
  如果全球图太大，请保持投影和 2:1 比例缩小。接口能检查尺寸，但不能判断图像是否真的覆盖全球，因此不要把局部地图裁成 2:1 充当全球图。
  需要处理局部高度图时，可以使用命令行的区域数据包入口。
- 导入会把映射与上述报告记进 `map.yaml` 的 `elevation_import` 块，并在 `registry.yaml`
  把 elevation 标为 `imported`、下游图层（气候等）标为 stale。
- **导入的高程进入正式构建**：API 保留原图与映射声明，地质构建从这份输入生成网格，气候继续在该网格上计算。
  上传后先更新预览栅格，正式网格在下一次构建时更新；无需手改全局 `elevation_source`。
- **导入的高度图不含板块构造数据**：plates 图层为空（左栏有提示），
  boundaries 图层回落到地壳底色。需要构造叙事时，用 geography 锚定 +
  管线生成，或把导入图当作"最终高程"接受无板块设定。
- **earth 验证世界是特例**：它的真实板块 + 地壳由专用脚本导入（PB2002 板块 +
  ETOPO1 水深判大陆架），不依赖上面的通用导入按钮：
  ```bash
  uv run python scripts/earth/import_earth_elevation.py \
      --output-dir <world>/maps/planet_earth --skip-download
  uv run python scripts/earth/import_earth_tectonics.py \
      --output-dir <world>/maps/planet_earth
  ```
  之后在 `terrain_config.yaml` 设 `elevation_source: imported`，地质引擎就会
  跳过合成管线、不覆盖已导入数据。
- 想"形状手绘、地貌物理补全"的中间路线：顶栏"⬆ 锚定灰度图"上传灰度概率图
  （存 `geography_raster.png`，白=陆/黑=海/中灰=中立），下次生成时与
  geography.yaml 叠加（`raster_weight` 调和）——形状是你的，地貌细节是物理的。
- 静态模式（GitHub Pages）为只读，按钮禁用。

### 7.1 后端导入链验收

基础自动检查覆盖两个导入端点的源图限制，以及映射、高程和海陆、
非零海平面、分支继承、旧网格遮蔽、删除产物后的重建，以及原图缺失与哈希损坏：

```bash
uv run pytest tests/test_map/test_import_elevation.py tests/test_map/test_elevation_import_build.py -n 0 -q
```

下面的命令创建一个小世界，经真实 API 导入，再运行地质与气候引擎，并输出图像和 JSON 报告。
脚本直接使用进程内 API，无需另开服务器。产物和样例世界写到本次生成的 `exports/elevation-import/` 子目录：

```bash
uv run python scripts/dev/accept_elevation_import.py
```

本地已有地球高程参照时，可附加 16 位、8 位与无海底的陆地灰度图对照。脚本只读地球高程和刻度，
在独立样例世界上构建，绝不构建 earth root：

```bash
uv run python scripts/dev/accept_elevation_import.py --earth-map data/worlds/earth/maps/planet_earth
```

检查 `sample-climate.png` 中陆地是否保留在原图位置、温度和降水是否完整；再读 `report.json`。
16 位往返的高程误差应落在一个保存台阶内，8 位量程图误差应落在半个源灰度台阶加保存误差内。
报告按源高程分组统计网格误差，按球面面积统计海陆变化，使用两组海岸像素的对称最近距离描述岸线位移。
这是相对于已有地球栅格的输入损失，不能当作独立海岸测绘精度，也不能代表气候模型的科学验收。
低平小岛消失时，其原海岸到剩余海岸的最近距离可能很大，因此最大距离不能解读成整条大陆海岸平移。
仅陆地图的海底误差单列为声明假设造成的损失，不套用灰度量化的误差门槛。

样例世界可以用下列命令进入已有查看器。把路径替换为脚本打印的实际样例数据目录：

```bash
uv run dreamulator serve --data-dir exports/elevation-import/<本次目录>/worlds --port 8001
```

在 API 模式查看样例时检查温度、降水、月度图层和单元格读数，切换平面与球面后核对位置。
导入、取消、错误恢复、预算和连续空间浏览的产品验收由
[前端入口提案](../design/proposals/frontend-entry.md#8-分阶段验收)维护。

### 锚定灰度图格式规范

**投影与朝向**：等距圆柱（equirectangular）。左缘 = −180°、右缘 = +180°、
上缘 = 90°N、下缘 = 90°S；像素中心按 `x = (lon+180)/360·W`、
`y = (90−lat)/180·H` 取用。±180° 缝合线两侧由作者自行保持连续
（管线按经度逐 cell 取像素，不会自动 wrap 混合）。

**分辨率**：任意。管线按每个 CVT cell 的中心**最近像素**采样，不重采样；
推荐 ≥ 2048×1024（低于网格密度时相邻 cell 共享像素，形状呈块状）。

**支持格式**（魔数自动识别）：

| 格式 | 说明 |
|------|------|
| 16-bit PNG（推荐） | 全精度 65536 级 |
| 16-bit TIFF（含 BigTIFF） | Gaea / World Machine 原生导出 |
| 32-bit float TIFF | 值应在 [0,1]；越界自动 min-max 归一 |
| 8-bit PNG | 接受但仅 256 级精度（日志警告） |
| 8-bit JPEG | 接受但仅 256 级且有损压缩，海岸线会变糊（日志警告）；主要面向聊天软件转发的图片 |
| 多通道 | 取第一通道（日志警告） |

**灰度语义**（归一后 0–1 → 偏置 −1–+1）：

| 灰度 | 偏置 | 语义 |
|------|------|------|
| 1.0（白） | +1 | 最强陆地锚定 |
| 0.5（中灰） | 0 | 中立，交给 feature/fBm |
| 0.0（黑） | −1 | 最强海洋锚定（抑制抬升+基准服从） |

**存储与生效条件**：上传后统一重编码为 16-bit PNG 存
`layers/geological/input/geography_raster.png`；仅当世界存在
`geography.yaml` 时生效（features 可为空列表，文件须在）；混合权重
`raster_weight` 写在 geography.yaml（默认 1.0，0=禁用）；带 `?branch=` 上传
存分支 geological input，未上传分支沿继承链向上取。

## 8. 常见问题

**Q: 生成太慢了，能加速吗？**

A: 降低 `num_nodes` 是最有效的加速手段（50k 约为 200k 的 1/4 计算量），适合快速
迭代；确定满意的配置后再用 200k 生成最终版本。性能剖析工作流见
[design/profiling.md](../design/profiling.md)。

**Q: 大陆形状太圆/太规则？**

A: 用 geography.yaml 锚定调整海陆分布（见 5.3），或上传锚定灰度图（见第 7 节）；
增大 `noise_persistence` 让海岸线更曲折。

**Q: 地图上为什么没有河流？**

A: 全球网格的 cell 约 51 km 宽，真实河谷都比它窄，所以地质层不在网格上计算汇流与
河网，地图查看器也没有河流图层。河流、排水与细节湖泊在高分辨率画布链上计算，见
[terrain-chain.md](terrain-chain.md)。网格上能看到的是湖泊：低于海平面、又不与全球
海洋连通的内陆盆地会被标记为湖泊（里海型），这是真实地貌，不是 bug。

**Q: 极地地区看起来不对？**

A: 等距圆柱投影在极地附近有水平拉伸。管线在球面 CVT 网格上运行，极地 cell 的
面积和邻居关系是正确的——切到 3D 球面视图查看真实比例。

**Q: 导出的高度图和查看器里看到的不一样？**

A: 查看器的「地形」着色包含山体阴影（hillshading），导出的 PNG 是纯海拔数据。

**Q: `num_nodes` 设太大（> 500K）会怎样？**

A: 生成时间与后续阶段计算量与 cell 数成正比；cvt_mesh 文件体积与前端解析内存
也随之膨胀（JS 堆 ~3–4× 原始体积是实际上限）。建议日常 200k。

**Q: 修改了 geography.yaml 需要重建整个地图吗？**

A: 不需要 `--force`——子阶段缓存按输入指纹自动失效，只重跑地理锚定之后的相位。
`--force` 只用于强制全量重建。
