# 查询构建进度

API 模式可以先发起后台构建，再查询各引擎的执行状态。前端使用 `api.startBuildJob`
传入世界名和构建选项，并保存返回的任务 ID；随后使用 `api.getBuildJob` 查询同一任务。
静态站不提供这种后台构建或任务进度查询。静态站气候实验台仍可在浏览器内运行试算。

## 页面操作

地图页的世界/分支栏也会显示构建计划：按 DAG 顺序排列各引擎层的图标，颜色区分最新、
输入已改和尚未构建；构建时当前层显示运行状态，已经完成的层逐层变为完成色。点击图标条
展开详细计划，可从最早需要重算的层直接发起构建，完成后地图原地刷新并显示正式结果。
该入口只在 API 模式的桌面端提供，参照世界根目录只读时不显示。

导入高度图后，可从平面图或球面的提示进入世界构建。先选择要构建的分支，检查面板显示的地形网格单元数，再点击「构建」。
能生成地形的目标显示其配置值；只继承或复用地形的目标显示已有网格的单元数，缺少记录时不猜测。
该界面不修改世界输入，也不改变地图的显示分辨率。
运行中，阶段明细会自动滚到当前计算。层级使用较大的圆点和文字，层内步骤缩进显示。
地质阶段显示生成网格、处理高程等操作，气候阶段分别显示温度、风场、洋流和每轮水汽求解。
如果引擎能报告处理量，当前步骤会显示已完成的网格单元、模型月份等实际计数。
完成数只说明执行了多少个步骤，不代表耗时百分比。页面显示步骤用时、总耗时和最近一次报告进度的时间，不估计剩余时间。
同一浏览器刷新页面后，会重新查询该世界和分支最近提交的任务；刷新不会再次启动构建。

构建结束后，面板显示结果摘要。展开「阶段明细」可查看这次任务执行或复用的各个阶段。面板仍可打开已保存的地图。
若构建失败，摘要会显示可用的错误信息；处理报错后再重试。若任务记录已不可查询，应先检查已有结果，再决定是否启动新构建。
「概览」介绍世界本身，不显示构建状态。「世界数据」页签继续提供已保存资料的入口。
在温度和降水图层中，图例与单元格检查器区分完整时段和当前月度时段。对声明了当地时间窗口的降水，
累计值按原窗口显示；如另有折算到参考年的值，检查器会分开列出。

## 发起与查询

以下请求在 `sample` 世界的 `climate-dev` 分支上重算气候。构建选项与同步接口一致：
`engine` 选择目标引擎，`branch` 选择分支，`start_layer` 从指定层及其下游开始，
`force` 要求重新计算目标。省略选项时使用世界根目录的完整管线及正常缓存规则。
真实地球等参照世界的根目录为只读，必须选择分支。

地图页的构建计划来自同一个引擎目录（`GET /api/worlds/sample/build-plan?branch=climate-dev`）：
它返回按 DAG 顺序排列的引擎层、每层的 `derived_fresh`（`fresh` / `stale` / `absent`）、
最早上游待重算层 `start_layer` 以及将要重算的层链 `recompute`；参照根返回 `read_only: true`。
该新鲜度是世界详情页使用的同一套磁盘检查（输入 YAML 比派生新即过期，地质层还包含
`maps/<planet>/`），属于显示用的启发式；真正的缓存失效仍由管线自己的检查决定。
每层都按构建范围内的产物判断，不依赖 `world.yaml` 是否列出了这一层：没有 authored
input、由引擎默认参数构建的层只看派生是否存在，分支目录内的产物优先于从根目录继承的产物。

```http
POST /api/worlds/sample/build-jobs
Content-Type: application/json

{"branch": "climate-dev", "start_layer": "climate"}
```

服务返回 HTTP 202 和任务快照。响应中的 `id` 是后续查询所用的任务 ID，初始 `state`
为 `queued`，表示请求已接收，后台函数即将执行。这一状态不代表有多个重算任务排队。

```http
GET /api/worlds/sample/build-jobs/{id}
```

前端可以每秒查询一次。运行期间，`state` 为 `running`，`current_engine` 标明当前引擎，
`elapsed_seconds` 给出开始执行以来的秒数。`updated_at` 记录最近一次收到阶段或子步骤报告的 UTC 时间，不是定时心跳。
如果当前操作耗时较长，时间线会停留在该操作，面板仍会显示已耗时。

## 理解阶段与结果

任务的 `stages` 列出本次构建实际选中的引擎。阶段状态含义如下。

| 状态 | 含义 |
|------|------|
| `pending` | 这个引擎已经选中，还没有开始检查输入。 |
| `validating` | 引擎正在检查缓存和输入。 |
| `running` | 引擎正在计算。 |
| `succeeded` | 引擎已经完成计算并成功返回。 |
| `skipped` | 已有输出仍然有效，本次直接使用缓存。 |
| `failed` | 引擎执行或输入检查失败，具体原因在该阶段的 `errors` 中。 |
| `not_run` | 构建提前结束，这个引擎没有执行。 |

`planned_steps` 列出当前计算路径预计执行的子步骤。引擎读取输入后可以调整这个列表，例如识别出已有高度图或指定的气候数据。
`steps` 按执行顺序列出引擎已经报告的子步骤。每项有 `name` 和 `started_at`；离开子步骤时记录 `finished_at`。
需要计数的步骤可以报告 `completed` 和 `total`。逐月水汽求解还报告 `pass_number`，每轮分别记录模型月数。
时间线不会把未执行的步骤点亮为完成。重复查询不会触发新的计算。

分支可能需要先补齐继承的天文数据。这项准备工作也作为真实阶段显示，阶段的
`bootstrap` 为 `true`，与正式分支计算分开计数。它沿用已有的上游准备规则。

构建结束时，任务状态为 `succeeded` 或 `failed`，`finished_at` 给出结束时间。
`result` 提供执行数量与错误汇总，其口径与同步构建一致：缓存跳过的阶段和上游准备
不计入 `engines_run`。运行异常另在任务的 `error` 中说明，已完成的阶段仍然可查。
所有阶段跳过缓存也算成功完成。

## 服务范围与重试

一个 API 服务进程同时只执行一项构建。同一世界的重复点击，以及其他世界在此期间
发起的构建，都会返回 HTTP 409；同步 `POST /build` 使用同一运行锁。任务结束后可以
重新发起请求，服务不会自动重跑失败任务。

通过本机 API 构建时，降水预算按月串行求解，页面仍可查询进度。需要使用多个进程计算月份时，可在支持该能力的宿主上通过命令行构建。

未知世界、分支或任务返回 HTTP 404。不存在的目标引擎或无效分支名返回 HTTP 422。
服务保留最近 100 个任务，任务状态存储在服务进程内。重启或开发模式热重载后，旧 ID
返回 HTTP 404；前端应说明该次状态已不可查询，再让用户检查结果和决定是否重算。
需要跨服务进程排队、断点恢复或长期任务存档时，另行设计持久化任务系统。
