# 浏览器气候实验台

气候实验台在浏览器内运行模型，目前提供年均和逐月温度。
世界「气候」页的「运行气候」按钮会打开当前天体和分支的实验。本机版完成全球高度图导入后，也可以从地图上的成功提示直接开始，不必先构建世界。「帮助」页提供不依附现有世界的地球和 Nacrea 样例。这些入口共用 `/playground` 页面。

平面地图和球面地图在全球高程可用时提供「气候实验台」。试算读取地图所选的天体和分支的全球高程，不会将区域选框作为计算范围。返回地图时保留通过 URL 记录的选区、图层和显示选项；试算不覆盖原有正式图层。
正式前端旅程由[前端入口提案](../proposals/frontend-entry.md)维护，完整浏览器计算候选由
[浏览器计算提案](../proposals/browser-playground.md)维护。

## 运行时与数据

`frontend/src/playground/temperature.worker.ts` 在首次计算时从站点自身加载 Pyodide 与 NumPy。同一页面的后续运行复用已经初始化的运行时，计算不占用界面主线程。
Vite 在开发和构建时准备这批文件。核心文件来自锁定的 `pyodide` npm 包，NumPy 的 WebAssembly 安装包从分发镜像下载，并按 Pyodide 的包清单校验 SHA-256。普通访客不需要连接第三方 CDN，也不会在打开页面时预先下载运行时。生成的运行时资源随站点发布，不入 Git。[Pyodide 上游源码](https://github.com/pyodide/pyodide/tree/314.0.7)对应当前锁定版本。
计算线程把 `engine/climate_physics.py`、`engine/climate_seasonality.py` 和
`frontend/src/playground/temperature_kernel.py` 的源码装入浏览器运行时，计算过程不需要 API 服务。
固定版本升级时须核对分发路径、numpy 包和源码兼容性。

试算使用 180 × 90 的等距圆柱规则网格。它读取当前分支的天体目录、全球高程和高程量程，沿用地图读取接口的分支继承。尚未生成天体目录时，试算读取已有的恒星系和行星输入。卫星的恒星距离与年长取自其宿主世界绕恒星的轨道，地表参数与自转取自卫星本身。简化模型使用自转周期的大小和不超过 90° 的季节倾角。若世界数据仍缺少参数，界面标明采用了地球样例默认值。

地球与 Nacrea 的独立样例图和高程元数据随页面构建，选择样例时同时载入对应参数。用户也可以选择图片，
图像经浏览器 Canvas 缩放并转为灰度，再用最小与最大高程线性换算成米。
这个解码器与正式 API 导入器不同：目前没有浮点 TIFF 原值读入、源分辨率海陆分类与独立海陆掩膜。
正式导入面板须实现[高程契约](map-system.md#高程语义与导入契约)，不能直接把原型解码器当作完整方案。

## 温度计算

内核先用辐射平衡和温室增温计算全球温度，再用一维能量平衡模型求纬向温度。
陆地高程通过递减率影响地面温度，季节热容量、月度日射和周期响应给出逐月温度。
它不计算完整气候求解器中的降水、水汽预算、风场、洋流和气候分类，也不会写回正式图层。

页面显示参数、灰度预览、温度图、年均与月份选择、均温、范围及耗时。修改参数后，页面保留并注明上次运行的结果，直到用户重新计算。页面按一月至十二月显示，仍按模型的春分起算索引读取对应结果。切换月份不启动新计算。
全球能量平衡温度与地表网格面积均温分别报告；它们不等同于完整世界的最终气候值。
规则网格与正式球面网格的逐格结果不能直接混作同一口径。

## 草稿与备份

从世界或地图打开的试算可以显式保存到「世界数据」。草稿保留来源天体、分支、参数和重采样后的输入高程。草稿不保存计算产物，重新打开后需再次运行。已保存的草稿不依赖原始世界地图重新下载。浏览器数据包在 `experiments/temperature/` 中包含草稿，不包含正式世界的图层与设定。旧数据包没有草稿条目，仍可导入。

## 从已有高度图创建世界

统一创建入口在本机版和静态站共用高程解码和海岸预览。它读取等距经纬投影、北方在上的非交错 8 位或 16 位灰度 PNG，要求长宽比为 2:1。用户为纯黑、纯白和海平面指定以米为单位的高程，像素按线性映射换算。TIFF、实际以米存储的图像和只有陆地信息的阈值映射由本机地图导入工具处理，不由这个创建分支承接。

创建步骤复用气候实验台的 Worker 和气温模型，但不使用样例页面的 Canvas 解码。预览和实验通过像素中心所在的源图像素采样。原始 PNG 及其高程映射进入地质层的正式输入，正式构建直接读取这份原图。与引擎兼容的天体参数写入天文和地质输入；用户在实验里指定的公转周期和递减率不覆盖正式构建的物理输入。

初始世界按完整世界快照格式打包，可用 CLI 恢复。静态站将同一个压缩快照写入浏览器存储；本机站将快照校验后还原到新的世界目录。两种保存操作都不启动构建。受支持的世界备份可在静态站世界列表恢复，不覆盖同名世界。

创建时可同时保存年均和逐月温度。软件记录内核源码的哈希、实际输入的指纹、温度单位、月份顺序和网格口径。温度文件位于 `layers/climate/derived/browser-temperature/`，不写入正式的球面网格。输入一旦变化，旧结果不参与保存。世界数据的二维预览可在关闭或刷新后直接读取保存的结果。

## 从起步模板创建世界

两种站点在同一页面提供基础行星和类地行星。两者使用同一套仓库模板，也使用相同的名称、世界 ID 和随机种子。静态导出将模板的世界配置和正式输入附到站点，浏览器据此生成带 SHA-256 校验的世界快照。本机 API 将同一个模板复制到新的世界目录。不论保存位置，创建过程都不写入高程、地图或任何计算产物，也不会为类地行星自动套用真实地球高程。

静态站可以从世界列表恢复浏览器创作生成的两类快照。起步世界的快照也可以用 `dreamulator snapshot restore` 恢复到本机。若要给起步世界添加全球高程，或由生成器计算地形，可在本机使用地图导入或正式构建。静态站的区域数据工具仍可单独给浏览器世界添加区域数据，但不会用区域数据替代全球高程。

## 限制与验收

首跑需要能从当前站点读取运行时资源。可独立打开的离线包与分享能力属于后续设计。
原型验收覆盖运行时加载、选图预览、运行失败、年均与月度切换，以及静态站内的本地计算。
性能样本须分别记录首次加载与内核计算，不能用单次计算耗时代表首屏加载时间。
正式入口验收另见[前端入口提案第八节](../proposals/frontend-entry.md#8-分阶段验收)。
