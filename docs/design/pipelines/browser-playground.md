# 浏览器温度实验台

温度实验台在浏览器内运行温度纯函数，用于检查高度图输入与年均、逐月温度的交互。
它是已实现的实验原型，页面为 `/playground`，默认入口受实验功能开关控制。
正式前端旅程由[前端入口提案](../proposals/frontend-entry.md)维护，完整浏览器计算候选由
[浏览器计算提案](../proposals/browser-playground.md)维护。

## 运行时与数据

`frontend/src/playground/temperature.worker.ts` 在首次计算时从站点自身加载 Pyodide 与 NumPy。同一页面的后续运行复用已经初始化的运行时，计算不占用界面主线程。
Vite 在开发和构建时准备这批文件。核心文件来自锁定的 `pyodide` npm 包，NumPy 的 WebAssembly 安装包从分发镜像下载，并按 Pyodide 的包清单校验 SHA-256。普通访客不需要连接第三方 CDN，也不会在打开页面时预先下载运行时。生成的运行时资源随站点发布，不入 Git。[Pyodide 上游源码](https://github.com/pyodide/pyodide/tree/314.0.7)对应当前锁定版本。
计算线程把 `engine/climate_physics.py`、`engine/climate_seasonality.py` 和
`frontend/src/playground/temperature_kernel.py` 的源码装入浏览器运行时，计算过程不需要 API 服务。
固定版本升级时须核对分发路径、numpy 包和源码兼容性。

原型使用 180 × 90 的等距圆柱规则网格。地球与 Nacrea 的样例图和高程元数据随页面构建，选择样例时同时载入对应参数。用户也可以选择图片，
图像经浏览器 Canvas 缩放并转为灰度，再用最小与最大高程线性换算成米。
这个解码器与正式 API 导入器不同：目前没有浮点 TIFF 原值读入、源分辨率海陆分类与独立海陆掩膜。
正式导入面板须实现[高程契约](map-system.md#高程语义与导入契约)，不能直接把原型解码器当作完整方案。

## 温度计算

内核先用辐射平衡和温室增温计算全球温度，再用一维能量平衡模型求纬向温度。
陆地高程通过递减率影响地面温度，季节热容量、月度日射和周期响应给出逐月温度。
它没有完整气候求解器的降水、水汽预算、风场、洋流与分类，也没有世界持久化和分支。

页面显示参数、灰度预览、温度图、年均与月份选择、均温、范围及耗时。修改参数后，页面保留并注明上次运行的结果，直到用户重新计算。页面按一月至十二月显示，仍按模型的春分起算索引读取对应结果。切换月份不启动新计算。
全球能量平衡温度与地表网格面积均温分别报告；它们不等同于完整世界的最终气候值。
规则网格与正式球面网格的逐格结果不能直接混作同一口径。

## 限制与验收

首跑需要能从当前站点读取运行时资源。可独立打开的离线包与分享能力属于后续设计。
原型验收覆盖运行时加载、选图预览、运行失败、年均与月度切换，以及静态站内的本地计算。
性能样本须分别记录首次加载与内核计算，不能用单次计算耗时代表首屏加载时间。
正式入口验收另见[前端入口提案第八节](../proposals/frontend-entry.md#8-分阶段验收)。
