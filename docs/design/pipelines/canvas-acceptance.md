# 画布链验收清单

本清单用于画布小试、区域模式与数据批次的验收。它把工程检查、科学检查和作者效果判断分开记录，
承接[竞品分析第 4.2.3 节](../competitor-analysis.md#423-terragenesis-的河网对照与本库的借鉴2026-11-11-调研)的分项评价方式。
管线实现由[画布链](canvas-chain.md)维护，地貌候选与专项指标由对应提案维护。

## 1. 记录范围与状态

每份回执先写明代码版本、输入与模型权重的校验和、种子、采用模式、地理范围、投影、实际格距、
气候和冰面的来源版本，以及检查覆盖的小窗口、单张画布或跨画布批次。
格均高程、点值高程和显示纹理分别命名；基岩、冰厚、含冰地表、路由高程和最终采用高程分别记录。

每项检查使用「通过」「未通过」或「未测」三种状态，附指标、预先确定的阈值和证据路径。
不适用的检查标为「未测」，同时解释原因与它对本次交付的影响。缺产品、无有效样本或只有模型派生参照，
均不能据此给出科学通过。代码与输入版本改变后，受影响的项目重新检查。

## 2. 分项检查

| 编号 | 检查对象 | 判定与证据 |
|---|---|---|
| E1 | 来源与阶段语义。 | 核对每项产品的输入版本、单位、掩膜和阶段连接。修改任何参与缓存的输入后，确认缓存失效；恢复断点后核对完成块与校验和。原图、供体、混合、路由与采用高程各自保留，冰厚只计入含冰地表一次。 |
| E2 | 确定性与重新生成。 | 固定输入、权重、种子和计算环境，分别比较独立重新推理、跨进程生成及断点恢复。报告最大差、分位数与不一致像素比例，预先声明逐位相同或数值容差；只读缓存的复用不能代替重新生成。 |
| E3 | 同源裁窗与跨区连续性。 | 同一母窗口裁切的重叠高程与掩膜应一致。独立窗口、同画布分块和跨画布接缝分别检查，不互相代替；跨画布报告地表、基岩、海陆、湖、河段存在性及有效流量比，同时报告每项的测量覆盖。 |
| E4 | 多尺度一致性。 | 从同一采用场按实际覆盖面积取样，核对粗尺度背景与声明的可信范围。比较约 180 m 与约 359 m 产品的同地理位置、配色及尺度口径；来源更新、重采样和显示细节分别归因，避免把不同信息量的输入直接比较。 |
| E5 | 海陆、冰面与水量账本。 | 海洋使用锚定连通外海与声明的类海湖判据，区分基岩水域和含冰地表水域。联合检查封闭盆地、人工边界、海峡与陆桥；气候重采样按父格面积检查水量守恒，覆冰及地表过程分别检查体积收支和边界通量。 |
| E6 | 水文相容性。 | 检查路由图无环、汇流与出口收支、湖泊级联、终端状态、入湖和出湖河段的衔接，以及过路湖逐月蒸发与蓄水亏缺。整图与外存路径在可容纳的小样例上按同一口径比较；河网阈值以物理起始流量声明。 |
| E7 | 地球科学参照。 | 选择信息量和尺度相同的真实地形或独立观测，检验山脊、谷地、坡向、排水关系及专项过程指标。生成模式加入原图插值、等频谱等幅度噪声、当前供体混合和当前 TD 重绘四个对照；地球原始 DEM 不称为粗输入候选同等信息量的对照。 |
| E8 | 作者效果与交付用途。 | 提供同范围、同配色的局部、区域与总览图，请作者判断山系联系、地貌质感、海岸与河湖表达是否符合用途。此项单独登记；工程检查通过不等于 TD 地貌效果通过，Nacrea 的作者判断也不代替独立科学验证。 |
| E9 | 资源、续算与交付完整性。 | 开跑前按任务尺寸估算主进程、工作进程、工作数组、模型、缓存与输出的峰值开销，并扣除正在运行的任务；超过可用内存一半时改为分块或减少并发。记录采样峰值、采样间隔、限制、退出码和超限动作，验证任务可停止、恢复且没有残留进程；最后核对清单与产物校验和。 |

专项地貌指标见[画布条件场提案第 4.2 节](../proposals/canvas-conditioning-structure.md#42-第-5-步地形条件场的格子印痕与连续重建)。
每轮固定其他条件，只新增一种生成干预。进入大批次前，小试需要同时交出数值证据与作者效果回执。

## 3. 现有工具的判定范围

`canvas generate` 的分块完成记录、`canvas status --verify` 的校验结果、区域模式的阶段缓存，以及
`scripts/dev/check_canvas_seams.py` 的 JSON 报告可作为工程证据，具体入口见画布链第 2.6 节和第 3.7 节。
接缝工具在数值超出已提供阈值、坐标配对不符或海陆、湖、河段存在性分歧时返回 1。
缺少完整的高程、冰厚、海陆、湖泊或河段覆盖，以及请求流量比却没有有效配对流量时，工具返回 2。
所有类别都有完整覆盖、已提供的阈值满足且没有上述分歧时，工具返回 0。
未给数值阈值时，退出码 0 仅表示已完成取样；此时报告明确说明不作为数值验收通过。

接缝准备先逐对清点已声明的地形分块、冰厚、海洋锚和水文文件，再核对阶段版本。
水文目录中的 `surface.json` 记录其地表标签；与当前选择的二次侵蚀标签不一致时，河湖数据需要重算。
接缝工具将标签缺失或不匹配的河湖记为未测。完整的空河网可以提供「该范围没有河段」的结果。
没有对应冰厚文件时，只能在该画布明确声明缺文件表示零冰厚的条件下采用零值。
地表减去冰厚得到的是该产品的基岩重建值，独立基岩来源仍需另外核查。
同一版气候与冰面标签也不能替代跨画布的空间连续性检查。
海洋连通构建、取样点海陆判断和高程取样采用同一地表，均计入二次侵蚀增量并保留浮点米值。
河段格坐标的原点位于画布左下像素的中心，接缝查询和同位置图按这个原点换算地理位置。

来源核查与高程采样可以只读取小型元数据、分块头和配对点像素。它们不需要重新建立整张画布的海洋连通图，
也不需要加载全部河段。完整 S4 检查再按各项实际覆盖分别验收。

S2 的 `prefer_out_of_core` 会根据整图峰值估算选择外存路径，部分分块阶段的 `worker_budget`
会约束并发；这些是当前已实现的资源决策，不构成全部长任务的统一准入门。
已知可用内存时，`worker_budget` 在单个工作进程超过预算或指定的并行数量放不下时抛出内存错误。
填洼、分块水文与二次侵蚀入口都检查指定数量，并按任务数限制实际并发；命令行显示所需内存、允许预算与调整建议。
内存读数缺失或阶段没有提供估算时继续使用既有 CPU 与任务数上限，主进程和共享状态的完整峰值仍须单独估算。
后台任务另需看门狗，超限先请求进程组退出，宽限期后仍存活时强制终止。
CUDA 任务不使用会妨碍虚拟地址预留的地址空间上限，实际限制按主机常驻内存与显存分别记录。

## 4. 回执格式

回执按 E1 到 E9 逐项填写下表，允许同一项按范围拆成多行。

| 检查编号与范围 | 状态 | 指标及阈值 | 证据与限制 |
|---|---|---|---|
| 填写本次检查编号和地理范围。 | 填写通过、未通过或未测。 | 填写实际测量值、单位、有效样本数和预先声明的阈值。 | 填写报告或图片路径，并说明未覆盖的范围。 |

最终回执明确列出本次采用版本、作者是否接受效果，以及仍待验证的项目。
资源采样峰值只代表采样时刻的观测，不能称为理论峰值；科学与创作两项验收分别签结论。
