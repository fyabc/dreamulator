# 守护轴的事实检查与决策台账

守护轴检查文档引用、输入变化和已接受决策依赖的事实。决策记录采用 ADR（Architecture Decision Record，即架构决策记录）的形式，保存结论及其依据。检查发现变化后，由作者决定保留结论、另写决策或弃用结论。设计理由见[守护轴提案](../proposals/harness.md)。

## 检查范围与结果

`dreamulator guard check` 检查所选世界或分支的有效文档和决策记录。文档检查覆盖各层输入目录中的嵌套 Markdown 文件；分支没有覆写的同名文件仍从父世界继承。决策台账使用最近的设计笔记目录，与世界文档的目录继承方式一致。

| 结果 | 含义 | 命令退出码 |
|------|------|------------|
| 检查没有发现问题。 | 所引用的模板可以求值，已登记的输入和事实与接受时的依据一致。 | 命令返回 0。 |
| `broken_ref` | 模板引用的字段不存在，包括循环或条件语句中的引用。 | 命令返回 1。 |
| `input_changed` | 决策所登记的某层 YAML 输入发生变化，需要复核依据。 | 命令返回 1。 |
| `fact_drifted` | 决策的模板值、声明集合或完整渲染正文与接受时不同，需要复核结论。 | 命令返回 1。 |
| `divergence` | 输入变化属于记录中明确声明的创作覆写。 | 只有这类提示时，命令返回 0。 |
| `not_run` | 缺少事实上下文、输入指纹或模板基线，文件损坏，或者模板无法求值。 | 命令返回 2，表示检查未完成。 |

同时存在多种结果时，未完成检查的退出码 2 优先于变化的退出码 1。命令输出列出记录路径、所属层和具体原因。这里的通过表示引用与已接受依据一致；科学验证仍使用守恒、收敛和独立观测的验收流程。

## 输入指纹与模板基线

每层输入指纹按排序后的相对文件路径及原始内容计算。检查包含嵌套目录中的 YAML 和 YML 文件。分支完整覆写一个文件时，父文件不参与该文件的指纹；使用 `_inherit` 合并的文件则同时登记实际参与合并的父文件。Markdown 叙事文字不参与物理输入指纹。

模板检查使用 Jinja 的严格未定义值规则。字段缺失会产生明确结果；语法错误、无效过滤器和计算失败会使检查显示未完成。页面展示继续使用原有的容错渲染。模板中显式提供缺省值的可选字段，以及原样展示模板语法的示例，按 Jinja 的正常语义处理。

接受记录时，程序在台账目录中的 `.guard-baseline.json` 保存模板声明值和完整渲染正文。完整正文支持循环内的局部变量、条件语句和声明的增加或删除。简单声明的既有基线仍可比较；既有循环模板缺少完整正文时，程序要求恢复相应依据，不能将未执行的比较显示为通过。

输入比较和事实比较独立执行。同一份 YAML 经新引擎计算得到不同值时，事实比较仍会发现变化。`divergence: intentional` 只将已声明层的输入变化转为提示。没有指定 `divergence_layers` 时，该声明覆盖记录登记的输入层；指定时只覆盖列出的层。它不豁免事实变化、断开的引用或未完成的检查。

## 接受与状态管理

新记录使用 `status: proposed`。`guard accept` 先检查事实上下文、所有模板、现有基线和容量，再保存七层输入指纹、模板基线及 `status: accepted`。空指纹保存为 YAML 空字符串。各文件采用完整临时文件替换，基线先于接受状态落盘。

已经接受的记录在输入和事实都没有变化时，重复执行接受命令不会写文件。已有变化、缺少依据或已经退休的记录不能通过重复接受来覆盖基线。作者复核后另写一条记录，并用 `guard supersede` 指向已接受的新记录；前提不再成立且没有后继结论时，使用 `guard deprecate`。

台账默认容量为 20 条可见且已接受的记录。`guard archive` 只设置 `archived: true`，保持接受状态及正文；归档记录继续接受输入和事实检查。显式弃用和被新记录取代的记录保留历史，但不再参与有效决策的漂移检查。

分支检查可以读取继承的台账。分支写操作要求该分支已有自己的设计笔记目录；作者先将所需记录复制到分支目录，再登记新的候选决策。接受、归档、弃用和替代操作都支持 `--branch`，只修改该分支的记录和基线。继承的已接受记录需要新的裁决时，应另写候选记录，不用接受命令覆盖原来的证据。

## 验证与实现入口

回归覆盖同输入事实漂移、嵌套输入、分支继承和完整覆写、合并输入、基线损坏、模板失败、条件与循环、接受失败时的文件保持、归档后的漂移、替代记录存在性，以及命令退出码。真实世界检查保持只读，既有记录缺少依据时如实报告未完成。

- [stale.py](../../../src/dreamulator/guard/stale.py)实现输入指纹、严格模板检查和基线比较。
- [adr.py](../../../src/dreamulator/guard/adr.py)实现容量管理、接受、归档、弃用和替代。
- [storage.py](../../../src/dreamulator/guard/storage.py)解析世界与分支目录，并保存小型台账文件。
- [cli.py](../../../src/dreamulator/cli.py)提供命令与退出码；命令配方见[CLI 指南](../../usage/cli.md#过期检测)。

采用的外部参照是 Michael Nygard 的[决策记录约定](https://www.cognitect.com/blog/2011/11/15/documenting-architecture-decisions)和 Jinja 的[未定义值规则](https://jinja.palletsprojects.com/en/stable/api/#undefined-types)。前者要求保留决策及其替代关系，后者提供严格求值能力。
