# 天球星历查询（sky ephemeris）

> **状态**：部分实现，立项日期 2026-11-01。引擎查询与命令行（M1）、消费方接线（M2）、前端天球视图（M3）、
> 背景天球与星空文化框架均已实现，技术参考见 [pipelines/sky-ephemeris.md](../pipelines/sky-ephemeris.md)，
> 前端操作见 [天球视图](../../usage/sky-viewer.md)。事件搜索与 N 体（M4）及地形地平线未实现。

## 1. 为什么做

天空位置原先只以零散原语出现在引擎里，例如潮汐锁定卫星的母行星位置、相位照度与食季比例。视频镜头规划、FUI 数据卡、
前端天体视图和世界历法都需要同一组数；catalog 已经存了完整的轨道根数，各消费方再写一份传播就会彼此漂移。
本提案把「在时刻 T、从天体 B 的 (lat, lon) 看去，天空里有什么」做成引擎的第一性查询，天空因此成为可查询的公共产物，
历法、潮汐和星座文化都读同一份结果。

## 2. 已定的设计选择

- **传播用两体开普勒。** 卫星的相互扰动与节点进动不进入现行查询，catalog 根数已能满足镜头、数据卡与历法的精度。
- **消费方只读 JSON。** Blender 与浏览器的运行时不导入引擎，渲染与 FUI 读取命令行或端点的同一份输出。
- **视图形态。** 前端以透视环视为主、方位等距半球圆盘为辅，不做可旋转的三维天球。
- **背景天球与恒星系分离。** 背景方向冻结为黄道系单位矢量，与时刻和观测者无关；星空文化只按编号引用背景目录，不复制坐标。
- **不编造自转轴。** 缺少自转轴方位的非锁定天体直接报错，不给默认方位。

## 3. 未实现：M4 事件与 N 体

| 内容 | 依据与做法 |
|---|---|
| 食、凌、掩食与连珠的时刻搜索 | 在现有查询上做事件搜索；跨多年的升落分类（慢自转世界的极夜开始）一并处理。 |
| N 体与长时段节点进动 | 接 `scripts/astro` 的 REBOUND 链，判断卫星相互倾角与节点进动在长时段是否需要。 |
| 匀速自转的锁定框架 | 现行框架把母天体钉在天顶；改为匀速自转后母天体按中心差摆动约 ±2e，需要时作为细化项。 |

M4 按消费方需要启动；有了第二个子命令时，`dreamulator sky` 再扩成命令组。

## 4. 非目标

- **大气折射、光行时与相对论修正。** 量级远小于一个像素。
- **真实地球星表。** 架空世界的星空由背景天球输入定义，是否为地球参照接入观测星表尚未决定。

## 5. 开放问题

- 世界的日历与时区（太阳日、季节和年的定义）如何暴露给命令行；当前时刻只按距 catalog 历元的天数输入。
- 观测点高程与地形遮挡：需要时从高度场生成本地地平线轮廓，现行查询使用理想球面地平。
- 是否加入真实地球星表，以及何时加入。
