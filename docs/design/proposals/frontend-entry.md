## 1 产品目标与用户

用户应当能先表达创作意图，再得到能够理解、检查和导出的结果。页面以用户正在做的事情组织，
学科层级作为结果来源和高级设置展开，首屏不要求用户理解引擎目录。

| 用户 | 进入时已有的东西 | 应当完成的事情 |
|------|------------------|----------------|
| 已有地图的作者是首条旅程的服务对象。 | 作者有高度图，并知道希望保留哪些地形。 | 作者声明高程映射，查看气候，选择窗口，生成高清地形并导出图片。 |
| 从设定出发的作者是后续服务对象。 | 作者有恒星、行星或海陆形状的想法。 | 作者从模板创建世界，修改允许的输入，并检查派生结果。 |
| 读者首先需要浏览入口。 | 读者有已发布世界的链接。 | 读者探索地图、季节与世界说明，并能返回原来的位置。 |
| 熟悉模型的作者需要高级入口。 | 作者有参数、分支和验证需求。 | 作者检查输入、派生事实和诊断来源，在网页版与命令行之间延续同一份世界。 |

面向普通用户的默认入口应是可直接使用的网页；本地服务与命令行面向需要完整计算、自定义参数或诊断的进阶用户。
静态入口的交付目标见[第 6.1 节](#61-面向普通用户的静态入口)。桌面应用保留为后续交付选择。

## 3 首屏与世界工作台

首屏提供三个动作。主要动作是「导入我的地图」，次要动作是「从模板创建世界」，浏览动作是「探索示例世界」。
进入已有世界时回到上一次工作位置，不要求重新经过创建向导。

工作台围绕当前世界、分支和选中对象组织。主区域显示平面地图、球面或恒星系；任务面板提供导入、计算、
选区和导出操作；检查面板解释选中位置的值与来源。高级作者可以展开学科输入与诊断，基础任务不依赖这些面板。

平面与球面切换保留经纬度、选区、图层和时间状态。进入恒星系时保留行星身份，返回时恢复视角。
分享链接首先恢复已发布的浏览状态；普通网址不假装包含私有图像和未发布的计算结果。

从模板进入时，作者先选择创作起点和必要输入，再构建与检查结果；输入表单逐步展开学科设置。
修改已有世界时，页面说明修改属于哪个分支、影响哪些下游结果，并保留比较与返回路径。
阅读已发布世界时，工作台提供专题图层和世界说明，依据实际部署能力开放编辑与计算动作。

实体检查面板也承接叙述与 AI 辅助的入口。用户先看输入、派生事实和证据，再按需要请求解释或创作建议；
建议作为可检查的输入修改或叙述候选，不直接覆写模型结果。命令与后端机制由
[AI 命令提案](ai-cli-commands.md)和[层级控制模型](layer-control-model.md)维护，入口按实际可用能力展示。

## 4 首条旅程：已有地图的作者

### 4.1 声明输入并预览

选择高度图后，浏览器先展示原图与海岸预览，用户确认后才保存或计算。面板应当提供：

- 用户声明灰度是否包含海底，或图像值是否已经以米计。面板据此显示量程，或海平面阈值与最大高程。
- 数字旁显示单位、默认值来源与简短解释。传递曲线与海底假设可放在高级设置，结果摘要始终说明实际采用的值。
- 预览显示海陆判定、尺寸与精度。像素占比与球面面积占比分别标注，等距圆柱图的像素比例不能称作行星面积比例。
- 目标分辨率变化时重新计算海岸与报告。独立海陆掩膜属于后续接口扩展，界面依据实际后端能力开放。
- 无法解码或包含缺失值时保留已填参数，指出需修正的输入，并允许重新选择文件。

网页目前只接受符合全球高度图契约的输入。区域地图导入属于 D 阶段的后续工作，当前只显示提示。
区域导入时，作者必须指定地图覆盖的经纬度范围。区域输入可用于局部地形细化，不能单独用于计算气候等依赖全球状态的结果。

公式、格式支持、源分辨率判海陆和原图保留方式由[地图系统的导入契约](../pipelines/map-system.md#高程语义与导入契约)
维护。前端预览不另写灰度曲线，而是调用后端只读预览接口，它与正式导入使用同一组解码与映射函数。
首页入口和地图页的导入按钮共用同一个导入面板。

### 4.2 选择计算并读取状态

浏览器温度原型提供快速预览，完整世界计算使用后端管线；页面分别标明模型、网格与用途。
从预览转到正式构建时保留原图和声明，重新计算正式结果。

长计算显示真实阶段、已耗时与最近更新时间。能估计完成时间时说明依据，缺少进度时只显示运行状态。

API 后台构建与阶段查询由[构建进度接口](../../usage/build-progress.md)提供，前端按真实阶段接线。
失败后保留输入和已完成结果，说明需要重试哪些步骤。后台任务状态必须能在刷新页面后重新读取。

学科管线以阶段结果提供反馈；月度气候是季节变化，不是构建进度。将来接入时间积分后端时，
其中间快照、尚未平衡的结果与已接受的最终结果分别显示。

### 4.3 理解气候与季节

正式结果先显示地形与一张易读的气候图层。用户切换温度、降水和分类，选中地点读取单位、时间窗口与来源。
图例解释颜色，缺失数据保持缺失，并给出获取相关结果的路径。

月度查看器已经存在，工作台复用年均与月度切换。光照可以连续变化，气候按实际时间窗口切换；
月序与零点从数据读取，降水按文件定义的累积窗口显示。没有逐月场的变量保持原时间口径。
瞬时天气入口仅在存在相应气象包时出现。接口与烘焙实现由[地图系统](../pipelines/map-system.md)维护。

### 4.4 选择窗口并获取高清结果

作者在平面图或球面图上选区，并在区域地图页预览、选择导出分辨率和下载高程。区域地图没有可复用结果时使用全球高程预览；
提高输出分辨率只做插值，不细化地形。两种高程下载格式与数据来源见[地图工作流](../../usage/map-workflow.md#46-选取区域浏览并下载高程图)。

本机网页可调用 Terrain Diffusion（TD）按输入场重绘地形，并保留原始高程供同视角对照。操作、环境与计算上限见[地图工作流](../../usage/map-workflow.md#本机网页细化)。后续应按实测提供耗时估计，并在超过设备预算时建议缩小窗口或降低分辨率。

已有高清窗口直接加载，未计算区域先显示全球地形。程序化显示细节标明为显示用途，不写回正式高程，
也不生成用于科学判断的河网。高清计算完成后，作者比较保留的原地形与细化结果，再选择采用的产物。

技术路线由[区域数据包](../pipelines/region-pack.md)、[画布链](../pipelines/canvas-chain.md)和
[外部精细化提案](gaea-refinement.md)维护。图片与窗口包包含图例、尺度、选区、输入假设和来源。

#### 4.4.1 按输入尺度推荐处理方式，作者可以切换

高清确认页区分「沿用原图地貌」和「按输入场重绘」两类意图。前者适合已有山脊、谷地和海岸的地图，
后者适合只规定大尺度地势的粗图，或希望重新设计地貌的作者。输入尺度用于推荐，作者的选择决定实际处理。
命令行的[区域构建](../../usage/cli.md#区域构建region-build)支持重绘、混合与只提取水文，默认使用重绘。
浏览器按作者声明的原生采样间距给出处理建议。默认只为粗输入选中重绘，间距未知或原图较细时由作者选择。
浏览器支持普通重绘、增强细节的重绘和混合细化。混合使用原图与模型生成高程之差的短波部分。增强重绘的细节
振幅可调整，默认是普通重绘的两倍。原始高程独立导出。
本机网页调用命令行的重绘、混合与水文模式。对照、裁切一致性和采用规则仍需按各模式验收。

| 输入与创作意图 | 推荐方式 | 用户应当看到的结果说明 |
|----------------|----------|------------------------|
| 约 50 km 的原生粗网格主要表达区域平均地势。 | 页面推荐按输入场重绘。 | 结果沿大尺度条件生成山地与谷地，原图未提供的小尺度结构属于生成内容。 |
| 约 350–360 m 的原图已经表达作者希望保留的山脊和谷地。 | 页面提示可以选择混合细化，由作者决定。 | 结果保留可信尺度内的原地形，并在更小尺度加入生成细节；海陆边界沿用输入判定。 |
| 原图虽细，但作者只把它作为地势草图。 | 作者可以切换为按输入场重绘。 | 页面明确说明山脊、谷地和局部海岸可能重新生成，并提供原图对照。 |
| 原图来自粗数据放大，或有效精度尚未声明。 | 页面按已知原生尺度推荐；未知时要求作者选择意图。 | 页面分别显示文件像素尺度、原生数据尺度与输出像素尺度，插值放大不增加有效精度。 |

默认推荐依据原生数据尺度、可信地形尺度和目标尺度之间的关系，不设一个适用于所有来源的固定公里阈值。
可信地形尺度指作者希望保留、且源数据足以表达的山脊与谷地大小。灰度图的高度量化、已有平滑和作者声明的
用途也进入摘要，较密像素不自动代表较高的高程精度。自动判断不从画面锐度猜出真实数据精度。

混合模式按物理长度划分原图结构与生成细节，过渡长度由源数据的有效尺度推导，并允许在高级设置中调整。
原型使用原图的长波部分与 TD 的短波残差合成；进入正式管线前须核查过渡附近的原有谷地是否被平滑、细节
是否重复叠加，以及纹理是否制造额外封闭盆地。原图海洋保持其输入高程，海陆掩膜与陆地合成分别处理，
不能只把被改写的深海压回海平面以下。合成先完成，再对实际采用的高程提取水文。

TD 接收约 23 km 的条件场，因此直接重绘不能保留 360 m 原图中已存在的所有地形。
增大高程约束强度只能影响 TD 实际读到的尺度，不能恢复缩小条件场时丢失的山脊。模型能力与条件强度由
[Terrain Diffusion 说明](../../knowledge/cartography/terrain_diffusion.md)维护。
已有地图无需生成细节时，还可以只处理水文；这项独立动作不要求运行 TD。

运行记录保存作者选择、推荐依据、原生尺度、输出尺度、混合过渡长度、输入哈希和生成参数。
模式与参数参与缓存识别，切换方式生成独立产物。对照页分别显示输入、生成或混合后的高程，以及水文处理后的
最终高程；检查值、河网和导出读取同一份采用结果。

模式验收使用同一区域的粗输入和细输入，并加入粗图放大后的对照。保留模式检查可信尺度内的山脊、谷地、
海岸和海底，重绘模式检查大尺度条件与细节质量；两者都检查边界深海、额外盆地和水文一致性。
量化报告包含分尺度高程差、海陆变化面积与盆地变化，创作验收同时提供原图与结果的固定尺度对照。
默认推荐及混合过渡参数在这些对照通过后进入正式入口。

## 5 连续空间浏览

用户应当明白自己一直在看同一个地点。先让平面、球面和已有高清窗口共享定位与返回路径，
再做地表到整球的相机原型；跨行星和恒星系的连续镜头在定位与尺度约定稳定后展开。

地表读取窗口细节，区域视图逐步回到全球地形，远景展示球面和大气。细节层级是按观看距离选用不同精度的数据；
切换时保留地物位置和主要高程，加载期间保留已有地形，避免空白和未经说明的形状突变。

相机原型验证坐标与深度精度，包括地面附近抖动、穿地、远景裁切和大跨度移动后的复位。
《戴森球计划》为游戏改变宇宙尺寸，本库继续保存真实物理尺寸。需要夸张显示高度或天体尺寸时，
说明呈现倍率并提供原比例查看，显示策略不改模型输入和科学导出。

Code Planet 的性能与实现仍待实测。WebGPU 可以作为增强路线，现有平面与球面查看器提供基础浏览。
测量后再决定目标设备、帧率和细节范围，不能把演示帧率直接套成本库指标。

## 6 三档计算与结果来源

| 档位 | 用户得到什么 | 界面需要表达什么 |
|------|--------------|------------------|
| 浏览器即时预览帮助用户确认输入与效果。 | 当前提供温度预览，后续能力由浏览器后端验收决定。 | 页面说明模型、网格、能力与加载状态，不把预览称为完整世界。 |
| 本机计算完成正式世界与窗口任务。 | 用户得到可复现的气候或指定范围内的地形。 | 页面显示范围、预算、阶段、来源与失败恢复，网页版和命令行共用数据。 |
| 重计算交付预先确定预算的产物。 | 用户加载已有世界数据、气象包和高清窗口。 | 浏览不要求重跑全部模型，缺失窗口可以另行提交计算。 |

结果分别说明作者输入、模型推演、真实观测与显示细节，并列出输入假设。科学验收检查预算、尺度与独立观测，
创作验收检查用户意图，两者分别报告，避免把派生结果当作独立真值。

API 模式提供写操作，静态发布模式可以浏览已发布的世界，并从已发布的全球高程截取和下载所选区域。
浏览器温度实验可以单独本地运行，但静态站不能保存世界或提交后端任务。

### 6.1 面向普通用户的静态入口

目标是让普通用户打开一个网址就能开始使用，既不用安装软件，也不用启动本地服务，而不只是浏览示例世界。[web-exoplasim 及其分支](../web-gcm-and-frontend.md#6-web-exoplasim-qol-的增强与边界)提供了可参照的流程：在浏览器内读取用户选中的文件，由用户保存项目或运行快照并在下次打开。

设计先确定普通用户在静态站能独立完成的最小流程，并明确哪些计算在浏览器内可以可靠地运行、如何保存和恢复自己的项目，以及设备不足或任务过大时如何提示。本地服务和命令行继续承担完整世界构建、进阶参数、分支管理和超出浏览器预算的计算。静态版单独验收：用户不启动后端，即可用自己的地图走完约定的基础流程，并能保存后再次打开。现有只读站与温度实验不算通过这项验收。

#### 静态站的地形细化

GitHub Pages 只提供网页和文件，不能运行本机的 Python 与 CUDA 推理。公开的 [30 m ONNX 模型](https://huggingface.co/xandergos/terrain-diffusion-30m-onnx/tree/main)不是本机链使用的 90 m 模型，文件合计约 2.28 GB，超过 [Pages 的 1 GB 站点上限](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)。即使把权重另行托管，浏览器还受内存和模型格式限制，见 [ONNX Runtime Web 的大模型说明](https://onnxruntime.ai/docs/tutorials/web/large-models.html)。

静态区域地图可使用当次选区的高程，在浏览器中依次运行 Terrain Diffusion 的粗级模型、基础模型和解码器。它与本机版共用设备栏，并保留原图供对比。操作和配置见[地图工作流](../../usage/map-workflow.md#静态站的浏览器细化)。浏览器入口目前只处理静态站已发布的全球高程，不接气候或水文。权重不打包进站点，浏览器按需下载并校验，然后保存在站点存储中供后续复用。面向普通用户发布前，还须验证常见设备的兼容性和本地高程图导入，并降低下载和运行开销。模型托管不可达时，可以考虑提供离线模型文件作为备用入口，文件仍由浏览器校验和读取。

如果实测门槛高于目标用户的设备能力，优先评估更轻的浏览器模型。可选远程 GPU 是单独的服务方案，必须事先说明上传的数据、保留期限和费用并获得用户确认。完整浏览器方案通过前，静态站对用户地图只提供已有全球图的截取与下载，不将插值标为地形细化。

## 8 分阶段验收

每阶段先提供可体验产物，再进入后续能力。验收针对最终行为，失败记录与性能样本单独归档。

| 阶段 | 可体验产物 | 通过条件 |
|------|------------|----------|
| A 验收输入到正式气候的连接。 | 提供小世界、导入报告、构建结果和地球量化对照。 | 原图与声明可重建同一地形；海陆和海平面传到气候；分支不改父世界；缺失原图明确失败；8 位误差与海岸位移单独量化。 |
| B 验收首屏、导入预览与工作台。 | 提供可点击的导入旅程。 | 未读 YAML 的作者能选图、理解单位、确认海岸并进入结果；取消不写盘，错误不清空已填参数，刷新后能找回世界。 |
| C 验收运行反馈与结果阅读。 | 提供长任务、失败任务和月度示例。 | 用户能在构建前确认地形网格数量，能辨认阶段、已完成结果与重试动作。图层、图例与检查值属于同一时间窗口，光照、历史、季节和任务进度不混淆。 |
| D 验收选区、预算、处理方式与导出。 | 提供已有窗口、待生成窗口及同区域的粗细输入。 | 作者看清范围、预算和处理方式，能比较原图与结果；推荐不因插值放大改变，返回全球后选区保留，导出带单位、尺度、范围和来源。 |
| E 验收连续空间浏览。 | 提供覆盖地面、海岸、山区、极区与整球的固定路线。 | 跨视图和精度切换后定位一致，无穿地、明显抖动或空白；记录帧耗时、加载和内存，再据目标设备确定可接受档位。 |

基础旅程同时检查 API 模式与静态模式。当前的静态站验收浏览已有结果，API 模式额外验收保存、计算和恢复。面向用户的静态入口按第 6.1 节单独验收。
无 WebGPU 的浏览器仍能进入基础查看器。鼠标、键盘和触屏分别检查选图、选区、复位与面板可读性。

## 9 仍需决定的事项

完整浏览器气候的后端、独立海陆掩膜接口、任务状态持久化、连续浏览的目标设备和高清数据范围尚需专项验证。
各项由验证结果决定实现，首条正式旅程先使用已有后端能力。

作者体验验收先覆盖导入与看结果，再评估精细化预算和连续浏览。入口改写不要求一次更换全部渲染与编辑系统。
