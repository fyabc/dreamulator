# 前端入口与用户旅程

> 状态：部分实现。网页支持从全球高度图或模板开始。静态站可在支持的已发布世界和浏览器自建高度图世界运行气候试算与区域细化。本机版支持完整构建、气候分支和世界备份。区域图的独立网页导入和连续空间浏览仍待完成。
> 立项日期：2026-11-04。
>
> 本文统一维护前端入口、用户旅程和交互验收。竞品证据由[竞品分析](../competitor-analysis.md)维护，
> 科学模型与已实现接口由各自的技术参考维护。实现时补齐旅程连接，复用现有查看器。

## 1 产品目标与用户

用户应当能先表达创作意图，再得到能够理解、检查和导出的结果。页面以用户正在做的事情组织，
学科层级作为结果来源和高级设置展开，首屏不要求用户理解引擎目录。

| 用户 | 进入时已有的东西 | 应当完成的事情 |
|------|------------------|----------------|
| 已有地图的作者是首条旅程的服务对象。 | 作者有高度图，并知道希望保留哪些地形。 | 作者声明高程映射，查看气候，选择窗口，生成高清地形并导出图片。 |
| 从设定出发的作者是后续服务对象。 | 作者有恒星、行星或海陆形状的想法。 | 作者从模板创建世界，修改允许的输入，并检查派生结果。 |
| 读者首先需要浏览入口。 | 读者有已发布世界的链接。 | 读者探索地图、季节与世界说明，并能返回原来的位置。 |
| 熟悉模型的作者需要高级入口。 | 作者有参数、分支和验证需求。 | 作者检查输入、派生事实和诊断来源，在网页版与命令行之间延续同一份世界。 |

面向普通用户的默认入口应是可直接使用的网页；本地服务与命令行面向需要完整计算、自定义参数或诊断的进阶用户。
静态入口的交付目标见[第 6.1 节](#61-面向普通用户的静态入口)。桌面应用保留为后续交付选择。

## 3 首屏与世界工作台

首屏提供三个动作。主要动作是「导入我的地图」，次要动作是「从模板创建世界」，浏览动作是「探索示例世界」。
进入已有世界时回到上一次工作位置，不要求重新经过创建向导。

世界列表用同一种条目展示已发布世界和浏览器世界。世界名称打开概览，有地图的世界可以直接打开地图；浏览器自建世界另有「世界数据」和「删除」。同一个浏览器可以保存多个独立世界，发布世界的浏览器成果归回原世界，不另列为新世界。创建或恢复后进入概览。「世界数据」负责已保存内容、备份与存储管理，不承担创建或计算。浏览器高度图世界从概览或参数页启动[网格与气候构建](../pipelines/browser-playground.md#完整-ebm)，无高度图的世界说明缺失的输入，不替换为示例地图。

工作台围绕当前世界、分支和选中对象组织。主区域显示平面地图、球面或恒星系；任务面板提供导入、计算、
选区和导出操作；检查面板解释选中位置的值与来源。高级作者可以展开学科输入与诊断，基础任务不依赖这些面板。

平面与球面切换保留经纬度、选区、图层和时间状态。进入恒星系时保留行星身份，返回时恢复视角。
分享链接首先恢复已发布的浏览状态；普通网址不假装包含私有图像和未发布的计算结果。

输入变化之后，结果如何在地图上呈现、何时过期、如何转正，由[开发工作台提案](development-workbench.md)维护：
正式结果来自上一次构建，开发结果来自当前输入；世界栏负责世界/分支状态与构建，地图栏负责地图自己的工具。

从模板进入时，作者先选择创作起点和必要输入，再构建与检查结果；输入表单逐步展开学科设置。
修改已有世界时，页面说明修改属于哪个分支、影响哪些下游结果，并保留比较与返回路径。
阅读已发布世界时，工作台提供专题图层和世界说明，依据实际部署能力开放编辑与计算动作。

实体检查面板也承接叙述与 AI 辅助的入口。用户先看输入、派生事实和证据，再按需要请求解释或创作建议；
建议作为可检查的输入修改或叙述候选，不直接覆写模型结果。命令与后端机制由
[AI 命令提案](ai-cli-commands.md)和[层级控制模型](layer-control-model.md)维护，入口按实际可用能力展示。

## 4 首条旅程：已有地图的作者

### 4.1 声明输入并预览

选择高度图后，浏览器先展示原图与海岸预览，用户确认后才保存或计算。面板应当提供：

- 用户声明灰度是否包含海底，或图像值是否已经以米计。面板据此显示量程，或海平面阈值与最大高程。
- 数字旁显示单位、默认值来源与简短解释。传递曲线与海底假设可放在高级设置，结果摘要始终说明实际采用的值。
- 预览显示海陆判定、尺寸与精度。像素占比与球面面积占比分别标注，等距圆柱图的像素比例不能称作行星面积比例。
- 目标分辨率变化时重新计算海岸与报告。独立海陆掩膜属于后续接口扩展，界面依据实际后端能力开放。
- 无法解码或包含缺失值时保留已填参数，指出需修正的输入，并允许重新选择文件。

网页目前只接受符合全球高度图契约的输入。区域地图导入属于 D 阶段的后续工作，当前只显示提示。
区域导入时，作者必须指定地图覆盖的经纬度范围。区域输入可用于局部地形细化，不能单独用于计算气候等依赖全球状态的结果。

公式、格式支持、源分辨率判海陆和原图保留方式由[地图系统的导入契约](../pipelines/map-system.md#高程语义与导入契约)
维护。前端预览不另写灰度曲线，而是调用后端只读预览接口，它与正式导入使用同一组解码与映射函数。
新建世界与给已有世界换图共用导入面板，但分别从创作入口与已有世界的地图进入。静态站的预览和解析遵循同一契约，见[统一创建入口](#统一创建入口)。

### 4.2 选择计算并读取状态

浏览器温度原型提供快速预览，完整世界计算使用后端管线；页面分别标明模型、网格与用途。
从预览转到正式构建时保留原图和声明，重新计算正式结果。

长计算显示真实阶段、已耗时与最近更新时间。能估计完成时间时说明依据，缺少进度时只显示运行状态。

API 后台构建与阶段查询由[构建进度接口](../../usage/build-progress.md)提供，前端按真实阶段接线。
失败后保留输入和已完成结果，说明需要重试哪些步骤。后台任务状态必须能在刷新页面后重新读取。

学科管线以阶段结果提供反馈；月度气候是季节变化，不是构建进度。将来接入时间积分后端时，
其中间快照、尚未平衡的结果与已接受的最终结果分别显示。

### 4.3 理解气候与季节

正式结果先显示地形与一张易读的气候图层。用户切换温度、降水和分类，选中地点读取单位、时间窗口与来源。
图例解释颜色，缺失数据保持缺失，并给出获取相关结果的路径。

月度查看器已经存在，工作台复用年均与月度切换。光照可以连续变化，气候按实际时间窗口切换；
月序与零点从数据读取，降水按文件定义的累积窗口显示。没有逐月场的变量保持原时间口径。
瞬时天气入口仅在存在相应气象包时出现。接口与烘焙实现由[地图系统](../pipelines/map-system.md)维护。

主图层和叠加层分别管理。海岸线、板块边界和流场等叠加层不受主图层切换影响；求解网格和降尺度是主图层的数据来源，不应与叠加开关混在一起。正式与试算产物应采用同一套结果描述，记录图层、单位、时间窗口、网格和来源。这样，保存世界可以直接保存试算已有的层，同时保留试算身份与缺失图层，不要求试算与正式构建使用同一种网格。

参照 [web-exoplasim 的自定义地形](https://github.com/ryoung48/web-exoplasim/blob/main/docs/climate/custom-terrain.md)与 [Pasta 气候后处理](https://github.com/ryoung48/web-exoplasim/blob/main/docs/climate/pasta.md)，界面应区分作者输入、求解网格上的结果和可选的降尺度产品。导入高程按原图尺寸显示，计算网格作为对照。以后只为有独立降尺度方法的变量提供切换，并注明使用了哪份细尺度输入和哪种方法。例如，近地面温度可按地形高度作订正；仅插值放大的气候图仍标为求解网格结果。分类图层应在已降尺度的物理量上重新计算分类。

### 4.4 选择窗口并获取高清结果

作者在平面图或球面图上选区，并在区域地图页预览、选择导出分辨率和下载高程。区域地图没有可复用结果时使用全球高程预览；
提高输出分辨率只做插值，不细化地形。两种高程下载格式与数据来源见[地图工作流](../../usage/map-workflow.md#46-选取区域浏览并下载高程图)。

本机网页可调用 Terrain Diffusion（TD）按输入场重绘地形，并保留原始高程供同视角对照。操作、环境与计算上限见[地图工作流](../../usage/map-workflow.md#本机网页细化)。后续应按实测提供耗时估计，并在超过设备预算时建议缩小窗口或降低分辨率。

从全球地图进入选区时默认显示全球高程截取，不自动选用已有细化结果。本机站和静态站都在顶部的「区域数据来源」列出同一世界、天体、分支和选区的可用成果。静态站在这里显示本次浏览器计算的结果，以及该浏览器已保存的成果。用户可以在原始高程和不同成果之间切换，不会重跑计算或写回全球高程。程序化显示细节标明为显示用途，不写回正式高程，
也不生成用于科学判断的河网。高清计算完成后，作者比较保留的原地形与细化结果，再选择采用的产物。

技术路线由[区域数据包](../pipelines/region-pack.md)、[画布链](../pipelines/canvas-chain.md)和
[外部精细化提案](gaea-refinement.md)维护。图片与窗口包包含图例、尺度、选区、输入假设和来源。

区域地图是地形细化工作台，与全球平面图共用工具栏、图层树和点位详情组件，但不照搬全球图层目录。左栏聚焦 Terrain Diffusion（TD）的五项物理输入：高程、海平面年均气温、月均气温标准差、年降水和月降水变异系数。柯本气候和群系不参与细化，不列入此处，但已有数据包仍保留这些数据。河网和径流属于后处理，与推理条件分组显示。缺失的区域图层置灰，右栏读取当前显示的栅格，不把像素当作全球模式单元。左下角的「细化地形」在右侧打开设备、计算设置、进度和导出面板，暂时覆盖点位详情。不能从当前成果再次细化时，左下角显示「高程与导出」。窄屏以抽屉呈现图层和细化设置。

虚线框外显示同一世界、天体和分支的全球地形参照，经纬网连续覆盖框内外。切换到细化条件图层时，框外仍显示地形，不以全球气温、降水或径流填补区域结果。找不到可靠来源时不填充。首次取景保留完整边界和周边；切换图层或高程对照不改变视角。框外参照来自当前世界，不是已保存成果的历史输入，也不参与点位查询、细化或导出。

#### 4.4.1 按输入尺度推荐处理方式，作者可以切换

高清确认页区分「沿用原图地貌」和「按输入场重绘」两类意图。前者适合已有山脊、谷地和海岸的地图，
后者适合只规定大尺度地势的粗图，或希望重新设计地貌的作者。输入尺度用于推荐，作者的选择决定实际处理。
命令行的[区域构建](../../usage/cli.md#区域构建region-build)支持重绘、混合与只提取水文，默认使用重绘。
浏览器按作者声明的原生采样间距给出处理建议。默认只为粗输入选中重绘，间距未知或原图较细时由作者选择。
浏览器支持普通重绘、增强细节的重绘和混合细化。混合使用原图与模型生成高程之差的短波部分。增强重绘的细节
振幅可调整，默认是普通重绘的两倍。原始高程独立导出。
本机网页调用命令行的重绘、混合与水文模式。对照、裁切一致性和采用规则仍需按各模式验收。

| 输入与创作意图 | 推荐方式 | 用户应当看到的结果说明 |
|----------------|----------|------------------------|
| 约 50 km 的原生粗网格主要表达区域平均地势。 | 页面推荐按输入场重绘。 | 结果沿大尺度条件生成山地与谷地，原图未提供的小尺度结构属于生成内容。 |
| 约 350–360 m 的原图已经表达作者希望保留的山脊和谷地。 | 页面提示可以选择混合细化，由作者决定。 | 结果保留可信尺度内的原地形，并在更小尺度加入生成细节；海陆边界沿用输入判定。 |
| 原图虽细，但作者只把它作为地势草图。 | 作者可以切换为按输入场重绘。 | 页面明确说明山脊、谷地和局部海岸可能重新生成，并提供原图对照。 |
| 原图来自粗数据放大，或有效精度尚未声明。 | 页面按已知原生尺度推荐；未知时要求作者选择意图。 | 页面分别显示文件像素尺度、原生数据尺度与输出像素尺度，插值放大不增加有效精度。 |

默认推荐依据原生数据尺度、可信地形尺度和目标尺度之间的关系，不设一个适用于所有来源的固定公里阈值。
可信地形尺度指作者希望保留、且源数据足以表达的山脊与谷地大小。灰度图的高度量化、已有平滑和作者声明的
用途也进入摘要，较密像素不自动代表较高的高程精度。自动判断不从画面锐度猜出真实数据精度。

混合模式按物理长度划分原图结构与生成细节，过渡长度由源数据的有效尺度推导，并允许在高级设置中调整。
原型使用原图的长波部分与 TD 的短波残差合成；进入正式管线前须核查过渡附近的原有谷地是否被平滑、细节
是否重复叠加，以及纹理是否制造额外封闭盆地。原图海洋保持其输入高程，海陆掩膜与陆地合成分别处理，
不能只把被改写的深海压回海平面以下。合成先完成，再对实际采用的高程提取水文。

TD 接收约 23 km 的条件场，因此直接重绘不能保留 360 m 原图中已存在的所有地形。
增大高程约束强度只能影响 TD 实际读到的尺度，不能恢复缩小条件场时丢失的山脊。模型能力与条件强度由
[Terrain Diffusion 说明](../../knowledge/cartography/terrain_diffusion.md)维护。
已有地图无需生成细节时，还可以只处理水文；这项独立动作不要求运行 TD。

运行记录保存作者选择、推荐依据、原生尺度、输出尺度、混合过渡长度、输入哈希和生成参数。
模式与参数参与缓存识别，切换方式生成独立产物。对照页分别显示输入、生成或混合后的高程，以及水文处理后的
最终高程；检查值、河网和导出读取同一份采用结果。

模式验收使用同一区域的粗输入和细输入，并加入粗图放大后的对照。保留模式检查可信尺度内的山脊、谷地、
海岸和海底，重绘模式检查大尺度条件与细节质量；两者都检查边界深海、额外盆地和水文一致性。
量化报告包含分尺度高程差、海陆变化面积与盆地变化，创作验收同时提供原图与结果的固定尺度对照。
默认推荐及混合过渡参数在这些对照通过后进入正式入口。

#### 4.4.2 查看条件场并对齐浏览器与画布

先开放查看真实条件场。高程保留原始与细化成果对照。有可核验记录时，用户还可以比较区域源数据与 TD 实际使用的条件网格，并查看其单位、尺寸和来源。只使用高程的运行标明「仅高程约束」；旧成果缺少可核验的输入时，不用当前世界的数据补作历史条件。重采样、块平均和折算至海平面不等于降尺度。只有同时具备可查询的源场和独立的细尺度产品时，才开放「降尺度」切换。

浏览器与本机区域包以 `region-td-grid-v1` 为共同的网格口径。输入是同一等距方位投影窗口内自北向南排列的五个格点场；先用年降水和地表高程把年均气温折算至海平面，再双线性重采样。目标网格约每 23 公里一个格点，每边至少两格；重采样保留源网格两端。送入模型时，高程取带符号的平方根，气温标准差乘以 100，再按模型规定的统计量归一化。画布可以独立选择高程和气候的采样策略，但进入模型时使用相同的通道口径。

已发布世界的静态站和本机区域包从同一分支的全球格网读取气候数据。浏览器自建世界则从用户打开的已保存 EBM 试算读取配套的高程和气候，不读取站点预存的条件。浏览器按需读取每格的气候统计和原生高程。气候统计优先使用科学精度数据；缺少科学伴档的旧构建也沿用本机的解量化规则。没有原生高度图时采用全球格网高程。没有完整配套气候时只用高程，并明确提示；文件损坏或读取失败时暂停运行，以免把读取错误误作没有气候。浏览器成果随备份记录实际使用的条件网格，并在区域图中复用条件图层与点位检查。验收对照同一窗口的五个网格与归一化输入，不要求不同推理后端产生逐像素相同的地形。独立的气候降尺度产品和多区域项目不阻塞 1.3 发布。

#### 4.4.3 多区域细化与画布项目

多区域细化作为可选的「画布项目」，不改变单个选区的操作路径。用户在全球图上圈定多个范围，并在项目面板查看每个区域的输入、排队状态和已采用结果。项目固定世界分支、输入版本、高程基准与目标采样尺度。项目先显示覆盖图、空缺和重叠带；用户可以只重跑受影响的区域，并在不改变现有成果的情况下比较和采用新版本。

拼接优先复用[画布的归属与过渡带](../pipelines/canvas-chain.md#24-归属与过渡带)，而不是在浏览器中把独立贴图硬拼在一起。先在共同坐标下确定重叠区归属和采用高程，检查高程突变、坡向、海陆边界及多块交会处，再从采用地表计算水文。前端区分局部预览河网和已核对的联合水文，并标出接缝处的出口、入流、湖泊和缺失的上游边界。相邻区域不齐时，不把未知入流当作零，也不凭河线看起来连通就判定汇水正确。联合计算和接缝验收复用[画布水文](../pipelines/canvas-chain.md#3-s2外存水文)与[画布验收](../pipelines/canvas-acceptance.md)。

先交付只读的多区覆盖与不同版本对照，再为一对相邻区域验证接缝、共同汇水和湖泊连续性，最后才开放批量生成、续算与联合导出。前端显示任务状态与诊断结果，大范围计算沿用画布管线，不能要求浏览器把所有高分辨率地形同时载入内存。该项目不阻塞 1.3 发布。

### 4.5 交互式工作流教程

首页提供可选的「开始教程」入口，帮助页提供重开入口。教程分为四段，每段只在到达相应页面后介绍当前操作。具体操作见[地图工作流指南](../../usage/map-workflow.md#从高度图走到完整世界备份)：

1. 导入示例全球高度图或用户自己的高度图，确认高程映射，在「世界参数」中查看或调整网格数量，然后构建世界。
2. 打开全球地图，查看正式气候及其逐月变化。在气候实验台调整参数运行 EBM，对照正式结果，并将试算保存为气候分支。
3. 在新分支选取区域，确认细化使用该分支的逐月气候与原图高程，运行 Terrain Diffusion 并保存区域数据包。
4. 回到世界概览，导出包含世界输入、已构建图层、分支和区域成果的完整世界备份。

教程复用真实页面与控件，每次高亮一个操作目标，并用简短提示说明要做什么、完成后会看到什么。步骤根据真实操作或任务结果推进，不能替用户提交参数、运行计算或导出文件。构建和细化沿用各自的进度、报错与重试界面。等待期间不锁住页面，退出教程也不取消任务或移除已保存的数据。

设计参考 Impeccable 的 `onboard` 指南，按任务分段而不是逐个介绍按钮。教程按标签页保存进度；跳过提示不代替操作，退出不清理世界数据。新目标首次出现在屏幕外时，页面自动滚动一次，但不移动键盘焦点。用户主动滚开后，可用「定位控件」返回。步骤提示不只依赖颜色或动画。静态站教程引导导入、查看和备份浏览器世界。浏览器试算和区域细化可以在地图上另行操作；完整构建和正式分支仍需要本机服务。

## 5 连续空间浏览

用户应当明白自己一直在看同一个地点。先让平面、球面和已有高清窗口共享定位与返回路径，
再做地表到整球的相机原型；跨行星和恒星系的连续镜头在定位与尺度约定稳定后展开。

地表读取窗口细节，区域视图逐步回到全球地形，远景展示球面和大气。细节层级是按观看距离选用不同精度的数据；
切换时保留地物位置和主要高程，加载期间保留已有地形，避免空白和未经说明的形状突变。

相机原型验证坐标与深度精度，包括地面附近抖动、穿地、远景裁切和大跨度移动后的复位。
《戴森球计划》为游戏改变宇宙尺寸，本库继续保存真实物理尺寸。需要夸张显示高度或天体尺寸时，
说明呈现倍率并提供原比例查看，显示策略不改模型输入和科学导出。

Code Planet 的性能与实现仍待实测。WebGPU 可以作为增强路线，现有平面与球面查看器提供基础浏览。
测量后再决定目标设备、帧率和细节范围，不能把演示帧率直接套成本库指标。

## 6 三档计算与结果来源

| 档位 | 用户得到什么 | 界面需要表达什么 |
|------|--------------|------------------|
| 浏览器即时预览帮助用户确认输入与效果。 | 当前提供温度预览，后续能力由浏览器后端验收决定。 | 页面说明模型、网格、能力与加载状态，不把预览称为完整世界。 |
| 本机计算完成正式世界与窗口任务。 | 用户得到可复现的气候或指定范围内的地形。 | 页面显示范围、预算、阶段、来源与失败恢复，网页版和命令行共用数据。 |
| 重计算交付预先确定预算的产物。 | 用户加载已有世界数据、气象包和高清窗口。 | 浏览不要求重跑全部模型，缺失窗口可以另行提交计算。 |

结果分别说明作者输入、模型推演、真实观测与显示细节，并列出输入假设。科学验收检查预算、尺度与独立观测，
创作验收检查用户意图，两者分别报告，避免把派生结果当作独立真值。

API 模式提供服务器端写操作。静态发布模式可以浏览已发布的世界，并从全球高程截取和下载所选区域。
静态站保存的世界数据只写入当前浏览器。发布的世界仍是只读底图和设定的来源。浏览器温度试算不需要本机计算服务。

### 6.1 面向普通用户的静态入口

目标是让普通用户打开一个网址就能开始使用，既不用安装软件，也不用启动本地服务，而不只是浏览示例世界。[web-exoplasim 及其分支](../web-gcm-and-frontend.md#6-web-exoplasim-qol-的增强与边界)提供了可参照的流程：在浏览器内读取用户选中的文件，由用户保存项目或运行快照并在下次打开。

设计先确定普通用户在静态站能独立完成的最小流程，并明确哪些计算在浏览器内可以可靠地运行、如何保存和恢复自己的世界数据，以及设备不足或任务过大时如何提示。本地服务和命令行继续承担完整世界构建、进阶参数、分支管理和超出浏览器预算的计算。静态版单独验收。用户不用启动后端，即可用自己的地图走完约定的基础流程，并能保存后再次打开。

#### 统一创建入口

首页、世界列表和侧栏的「新建世界」打开同一页面。页面按用户已经拥有的材料组织，不要求先选存储方式或了解引擎层级。

| 起点 | 用户怎样创建世界 |
|------|----------------|
| 我想从全球高度图开始。 | 用户上传自己的高度图或使用地球示例，确认高程映射、海平面和预览，然后保存世界。创建不运行气候。 |
| 我想从头创建。 | 用户选择起步模板，调整少量基本设定，再保存世界。没有高程也可以保存，之后可导入高程，或在有地形生成能力的环境中生成。静态站不自动套用地球高程。 |

本机版与静态站使用相同的步骤和按钮。在最后一步说明保存位置：本机版默认使用本机世界目录，静态站默认使用此浏览器。静态站在预览、运行和保存期间不上传原图。完整构建保留在本机版与命令行，保存本身不触发构建。确认前不创建世界，保存失败保留当前输入与可用结果，重试不留下半成品或覆盖同名世界。

气候实验台不另设侧栏主入口。浏览器自建世界可以从列表或世界标题旁直接进入共用的全球地图。已有世界的「气候」页和帮助页的样例也引导用户进入地图中的实验台。「世界数据」只管理存储占用、已保存成果、备份和删除。「恢复世界备份」和浏览器世界的快捷删除入口留在世界列表，不在数据页上传高度图。本机 API 模式的后续方向是参数实验台：只编辑并保存输入，由顶栏的正式构建发起计算；见[参数归属设计](parameter-ownership.md)。

#### 将气候实验保存为世界

浏览器世界与本机世界共享输入和派生图层的结构，不要求两种环境已生成相同数量的图层。缺少的层显示「尚未生成」。

- 世界输入保存原始全球高度图及其导入声明，包括投影、高程映射、海平面、尺寸和原图哈希。天体及气候参数写入正式构建能读取的输入。只对实验模型有意义的参数单独记录，不强行改写天体设定。实验用的 180 × 90 网格不是原始高程，不能代替原图用于地图、区域裁切或后续构建。
- 已运行的年均和逐月温度作为世界的派生图层保存，并记录单位、月份口径、网格、模型版本和实际输入的指纹。地图明确区分「浏览器气候实验」与正式构建结果。修改影响结果的输入后，用户可重跑，或只保存输入；不能把旧结果挂到新参数下，也不能以规则网格冒充正式球面网格。
- 世界备份保留原图、参数和已保存的结果。静态站可以从世界列表恢复整包并直接查看结果。本机可以从包中恢复正式输入并按需构建，不把浏览器的试算直接写成正式图层。恢复不依赖原网页、原文件选择或重新运行实验。浏览器数据包与本机完整世界快照按各自契约读取。

两条创建路径及备份的实现见[浏览器创作的技术参考](../pipelines/browser-playground.md#从起步模板创建世界)。静态站可把起步世界保存为包含正式输入的快照，但不在浏览器内生成全球地形。给同一个起步世界补入全球高程时，可以先在本机恢复，再使用现有地图导入工具。

#### 世界参数与试跑

参数试跑列入静态创作入口的首批，不等完整浏览器气候求解器。参照 [web-exoplasim 的交互](../web-gcm-and-frontend.md#6-web-exoplasim-qol-的增强与边界)，用户可以从已有世界打开试跑草稿，接受当前输入或调整少量有明确单位和作用范围的参数，再显式重跑。首批以温度试跑验证流程，只显示模型实际使用的输入。已发布世界保持只读；实验参数和结果不改写发布基线，也不冒充正式世界图层。

首批温度入口、重跑与草稿备份见[浏览器气候实验台](../pipelines/browser-playground.md)。完整世界重建继续由本机服务与 CLI 承担。通用设定编辑器由[参数实验台](parameter-ownership.md)承担，不塞进浏览器试算入口。

##### 统一到全球地图

已有世界只在全球地图中试算。平面与球面共享同一实验会话，用户可用「模式」下拉框在「正式」和「试算」之间切换，不必重新计算。两种模式共用图层列表、单元格检查和世界统计，并以相同方式处理缺失数据。试算数据的来源及统计口径见[地图内的气候试算](../pipelines/browser-playground.md#地图内的气候试算)。

「世界数据」中的草稿直接打开来源天体和分支的全球地图，并从草稿恢复参数和已保存的输入高程。旧 `/playground` 草稿链接保留兼容跳转。来源地图不可用时，保留能够读取已保存高程并重跑的恢复界面，不能以当前底图代替草稿中的输入，也不能把缺少地图当作草稿丢失。

帮助页的地球和 Nacrea 样例直接进入对应的全球地图。只有原始高度图的用户可以选择「从全球高度图开始」，无需先构建世界。独立的 `/playground` 路由只处理[旧链接跳转](../pipelines/browser-playground.md#草稿结果与备份)，不再提供单独的试算入口。

##### 气候求解器与时间模式

「正式」和「试算」选择结果来源；进入试算后，在气候实验台中选择求解器。EBM 是能量平衡模型，在这里指 Dreamulator 的完整快速气候管线，不是仅解温度的预览。EPS 是以原版 ExoPlaSim 为数值参照的 WebGPU 大气环流模型。EPS++ 是单独标识的扩展模型，可增加动态洋流等耦合过程，不改变 EPS 的对照基线。面板只显示当前求解器实际使用的参数和可用能力。本机正式构建的模型选择由分支的 `climate_source` 决定，不放进参数实验台；这里的选择只影响浏览器试算。

| 求解器 | 地图上的时间模式 | 运行时反馈 |
|---|---|---|
| EBM 按阶段求解整个气候态。 | 提供年均与逐月结果，不显示「当前」。 | 显示正在求解的阶段、阶段用时和累计用时。只有来源明确的子进度才显示计数。 |
| EPS 和 EPS++ 按时间步积分。 | 在可用的图层上显示「当前」，并在累计完成后提供月度与年均。 | 显示模式日期、积分目标、步速与预热状态。用户暂停时保留最后一帧。 |

三种求解器共用图层列表、色标、单元格检查、统计和月份柱形图。结果描述应记录求解器及版本、输入指纹、原生网格、图层物理含义与单位、可用时间模式，以及每个时段的平均或累计口径。只有物理含义相同的图层共用名称和色标，例如近地面气温不能用地表皮肤温度代替。结果保留各自原生网格，地图负责投影；没有同口径数据的图层按缺失处理，不从其他求解器拼接。

「当前」是最近一次已发布的瞬时场，不是按月均值补出的动画。积分和显示采用独立频率，查看器只取最新帧，不排队绘制每一个时间步，也不把每步的全球场复制回主线程。预热期间可以查看当前天气，但未完成的统计窗口不能标为月均或年均。分类等只依赖长期统计的图层不提供「当前」。

试算继续隔离输入与结果。改变参数后，旧结果仍标明它来自上一次运行；切换平面与球面不重启计算。写入世界或分支需要显式保存，保留来源、运行输入和时间口径，不改写发布基线。执行后端、结构化进度和验证顺序见[完整气候接入](browser-playground.md#完整气候接入与验证顺序)。

#### 正式世界参数编辑

世界工作台的「世界参数」在首次构建前和查看结果后使用同一个入口。可编辑项及其保存规则见[正式网格参数](../pipelines/browser-playground.md#正式构建的网格参数)和[正式天体参数](../pipelines/browser-playground.md#正式构建的天体参数)。本机 API 模式的后续方向是把正式参数编辑并入参数实验台：只保存输入并按消费者层标脏，计算由顶栏的正式构建发起，见[参数归属设计](parameter-ownership.md)。

本机可在可写世界或分支保存正式输入。静态站只能编辑自有副本；已发布世界与真实地球参照保持只读。正式世界参数与气候实验参数分别保存。验收覆盖创建后首次调整、构建后修改与重建、分支隔离，以及旧结果和新输入的区分。

##### 参数页的组织

所有正式参数集中在「世界参数」页签。各学科页签负责展示结果；需要引导编辑时，链接到统一参数页里的对应分组，不再放一套表单。参数按用户能辨认的主题组织，先设「天体」和「地形与网格」，再按可编辑项增加「大气与气候」等分组。每项只出现一次；分组不改变输入归属和分支继承规则。

紧凑行与详情的当前实现见[参数页布局](../pipelines/browser-playground.md#参数页布局)。暂不预留空分组；低频选项的折叠和参数搜索等字段增多后再评估。

[web-exoplasim](../web-gcm-and-frontend.md#6-web-exoplasim-qol-的增强与边界)按主题展示常用输入，[World Orogen](https://github.com/raguilar011095/planet_heightmap_generation/blob/main/docs/generate.md#controls)折叠低频地形设置，[ExoPlaSim](https://exoplasim.readthedocs.io/en/latest/tutorial.html#configuring-the-model-for-toi-700d)提供可移植配置，但不要求用户直接编辑底层输入文件。Dreamulator 暂不提供网页 YAML 编辑器，高级用户继续使用本机输入文件和 CLI。确有网页批量编辑或复用配置需求时，再考虑只在本机版开放受支持的输入文件，明确写入目标和分支，保存前展示差异并校验。保存仍不启动构建。

#### 静态站的世界数据

世界是网页和本机共用的数据归属单位。世界页的「世界数据」管理浏览器保存的原始资料、生成参数和用户选定的结果。地图选区的结果直接归入来源世界，并保留行星、分支和区域范围。新建世界使用[统一创建入口](#统一创建入口)。临时预览在用户保存后才成为世界数据。

已发布世界与浏览器世界共用列表、概览和学科页签。来源标签同时用文字和颜色区分。学科页签区分输入设定、已保存结果和缺失数据，不把浏览器快照内的设定当成计算结果。列表、概览和侧栏使用同一个地图入口；浏览器世界已有气候时，这个入口直接打开最近保存的结果。历史结果仍可从「世界数据」逐项打开。

侧栏将站点入口和当前世界的页面分组。世界概览、地图和恒星系等页面在内容顶部显示当前世界与分支，不依赖侧栏展开。切换世界打开目标世界的概览。切换分支通常保留当前页面，但不会沿用其他分支的试算或区域成果。区域地图从全球选区或已保存的成果进入，顶部沿用同一组件，并按实际来源标明分支。天球视图在本机版与静态站共用界面，计算数据与使用条件见[天球星历](../pipelines/sky-ephemeris.md)。

浏览器世界与本机可构建世界在「概览」和「世界参数」中共用「世界构建」卡片。两者都提供「下载世界备份」「检查基础设定」和「构建」，并以相同格式显示可用的地图结果和构建阶段。按钮的悬停说明标明操作范围：浏览器检查和备份当前浏览器保存的数据，只构建全球网格与 EBM 气候；本机运行完整世界管线，并可备份正式分支。浏览器备份也可从「世界数据」下载。地图统一从世界标题旁打开，不依赖上一次构建的任务记录。

浏览器世界数据包使用世界目录的相对路径。区域高程和地理范围沿用本机区域地图的 `packs/`、`height.meters.npy` 与 `meta.json`。已发布世界的数据包只带该世界的本地新增资料，以世界 ID 归位，保留站点原来的底图与设定。自建世界如何携带全球高程和气候结果，见[将气候实验保存为世界](#将气候实验保存为世界)。

世界数据和模型缓存分别管理。验收时在另一个浏览器导入世界数据包，确认原图、参数和选定结果无需重新计算即可恢复。清理模型缓存后，仍可打开原有世界数据。单张 PNG 或 TIFF 可以独立下载。

#### 完整世界快照

本机服务和命令行支持[完整世界快照](../../usage/cli.md#完整世界快照)，使作者能把已有正式构建结果迁到另一处继续查看，不必重新计算。浏览器本地备份只包含该浏览器保存的资料，不复制发布数据或模型缓存。如果以后能在浏览器内完整构建世界，保存的各层结果也应纳入可恢复的快照。

首版用导入 4096 × 2048 高程图并已完成构建的独立世界验收。导出的快照须能恢复到空数据目录，不覆盖同名世界，也不触发重新构建。恢复后应能打开逐月气候、计算网格及其他已生成的图层，并校验恢复的关键文件与导出时一致。网页导入器和静态站对完整快照的支持不属于首版。

后续如提供网页恢复，建议从本机世界列表选择「恢复世界备份」。选文件后先显示世界名称、已有图层、区域数量和所需空间，确认后再写入；同名世界不默认覆盖，成功后直接打开恢复出的世界。单张高程图下载用于分享或交给其他工具，世界备份用于换设备继续工作；两种入口不互相替代。独立区域地图导入仍另行评估。

#### 静态站的地形细化

GitHub Pages 只提供网页和文件，不能运行本机的 Python 与 CUDA 推理。公开的 [30 m ONNX 模型](https://huggingface.co/xandergos/terrain-diffusion-30m-onnx/tree/main)不是本机链使用的 90 m 模型，文件合计约 2.28 GB，超过 [Pages 的 1 GB 站点上限](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)。即使把权重另行托管，浏览器还受内存和模型格式限制，见 [ONNX Runtime Web 的大模型说明](https://onnxruntime.ai/docs/tutorials/web/large-models.html)。

静态站可以使用已发布世界的选区高程，也可以在世界页导入方形灰度高程图。浏览器依次运行 Terrain Diffusion 的粗级模型、基础模型和解码器，保留原图供对比。操作和配置见[地图工作流](../../usage/map-workflow.md#静态站的浏览器细化)。浏览器细化只处理高程，不接气候或水文。权重不打包进站点，浏览器按需下载并校验，然后保存在站点存储中供后续复用。面向普通用户发布前，还须验证常见设备的兼容性，并降低下载和运行开销。模型托管不可达时，可以考虑提供离线模型文件作为备用入口，文件仍由浏览器校验和读取。

如果实测门槛高于目标用户的设备能力，优先评估更轻的浏览器模型。可选远程 GPU 是单独的服务方案，必须事先说明上传的数据、保留期限和费用并获得用户确认。区域截取可以在没有细化模型时独立使用；截取与插值不标为地形细化。

## 8 分阶段验收

每阶段先提供可体验产物，再进入后续能力。验收针对最终行为，失败记录与性能样本单独归档。

| 阶段 | 可体验产物 | 通过条件 |
|------|------------|----------|
| A 验收输入到正式气候的连接。 | 提供小世界、导入报告、构建结果和地球量化对照。 | 原图与声明可重建同一地形；海陆和海平面传到气候；分支不改父世界；缺失原图明确失败；8 位误差与海岸位移单独量化。 |
| B 验收首屏、导入预览与工作台。 | 提供可点击的导入旅程。 | 未读 YAML 的作者能选图、理解单位、确认海岸并进入结果；取消不写盘，错误不清空已填参数，刷新后能找回世界。 |
| C 验收运行反馈与结果阅读。 | 提供长任务、失败任务和月度示例。 | 用户能在构建前确认地形网格数量，能辨认阶段、已完成结果与重试动作。图层、图例与检查值属于同一时间窗口，光照、历史、季节和任务进度不混淆。 |
| D 验收选区、预算、处理方式与导出。 | 提供已有窗口、待生成窗口及同区域的粗细输入。 | 作者看清范围、预算和处理方式，能比较原图与结果；推荐不因插值放大改变，返回全球后选区保留，导出带单位、尺度、范围和来源。 |
| E 验收连续空间浏览。 | 提供覆盖地面、海岸、山区、极区与整球的固定路线。 | 跨视图和精度切换后定位一致，无穿地、明显抖动或空白；记录帧耗时、加载和内存，再据目标设备确定可接受档位。 |

基础旅程同时检查 API 模式与静态模式。当前的静态站验收浏览已有结果，API 模式额外验收保存、计算和恢复。面向用户的静态入口按第 6.1 节单独验收。
无 WebGPU 的浏览器仍能进入基础查看器。鼠标、键盘和触屏分别检查选图、选区、复位与面板可读性。

## 9 仍需决定的事项

完整浏览器气候的后端、独立海陆掩膜接口、任务状态持久化、连续浏览的目标设备和高清数据范围尚需专项验证。
各项由验证结果决定实现，首条正式旅程先使用已有后端能力。

作者体验验收先覆盖导入与看结果，再评估精细化预算和连续浏览。入口改写不要求一次更换全部渲染与编辑系统。
