# 浏览器计算路线

> 状态：部分实现，温度实验原型已实现，完整气候与资源产品化仍为候选。
> 立项日期：2026-10-23。

## 目标与已有基础

浏览器计算让作者在本地确认输入并获得预览，无需先启动服务器。
现有温度原型的运行时、网格、输入、界面与限制由[技术参考](../pipelines/browser-playground.md)维护。
首屏入口、导入预览、参数说明、错误反馈与结果阅读由[前端入口提案](frontend-entry.md)统一设计。

## 尚未实现的计算路线

完整气候接入首先需要验证水汽预算的计算成本、守恒与收敛，之后才能决定可接受的网格规模。
数组化球面网格、共享内存 Worker 与 GPU 计算是候选，依据见
[浏览器 GCM 调研](../web-gcm-and-frontend.md)，它们不意味着现有原型已经具备完整世界能力。

运行时本地镜像、离线资源包和可分享输入需要明确加载、缓存、文件保留与结果版本的契约。
它们可以改善浏览器交付，但正式世界与本地预览仍应说明各自的模型和数据来源。

## 完整气候接入与验证顺序

1. **先复用本机 EBM。** 正式构建与隔离试算应调用同一套气候输入解析、求解和产物导出逻辑。首片读取现有地质网格的隔离副本，不重跑地质或后续层，也不调用会写回正式地图的完整构建入口。同一输入、网格和引擎版本下，对照正式构建的年均、逐月结果和分类；使用 4K 地球模型样例及 Nacrea，真实地球参照主干只读。没有现成地质网格的高程导入流程，需先通过正式地质路径准备网格。
2. **随首片接入结构化进度。** 在求解器中报出温度、风场、洋流、降水、分类和结果整理等阶段，外层任务另报读入与导出。复用正式构建的任务反馈设计，但不解析终端日志，不把事后统计的耗时当作实时进度。降水等任务仅在工作总量已知时报告已完成的月份或单元；未知时显示当前子阶段和耗时，不提供虚假的百分比。取消能力以执行后端能够安全终止任务为准。
3. **将静态站作为独立验收门槛。** 浏览器优先验证能否复用同一物理实现、同一结果契约。重点测稀疏求解依赖、串行与并行的资源预算、峰值内存及数值一致性。不把现有规则网格温度预览换个名字当作完整 EBM，也不在静态站自动上传用户输入或静默改用另一套模型。
4. **再接 EPS，最后扩展 EPS++。** EPS 在同初始条件、边界条件、物理开关、分辨率和时间步长下，对照固定版本的 Fortran ExoPlaSim。短程检查数值与预算，长程比较气候统计和空间分布，不要求两个混沌轨迹长期逐格一致。[ExoPlaSim 的快照与高频输出](https://exoplasim.readthedocs.io/en/latest/source/exoplasim.html)可作为拆分积分步长与显示采样频率的参照。EPS++ 在 EPS 通过对照后逐项加入耦合过程，先检查守恒，再验证气候影响。用户看到的时间模式由[气候求解器与时间模式](frontend-entry.md#气候求解器与时间模式)定义。

EBM 和 GCM 的输出对齐不要求同时拥有全部物理过程。云量列入独立科学工作：先验证逐格逐月的云量诊断能否通过独立参照，再决定短波与长波反馈是否能改善辐射收支、温度和降水。总云量不能替代云顶结构，也不以降水着色冒充云。已有约束、候选与否证结果由[柱辐射场提案](column-radiation-field.md)维护。它不阻塞完整 EBM 的试算接入，也不为 EBM 增加瞬时云帧。

## 验收与不采用的方向

计算后端分别验收宿主与浏览器的数值一致性、守恒、收敛、内存和运行时加载成本。
采用新的并行或 GPU 路线时，先在同输入、同网格上核对结果，再评估交互收益。
不以降低科学口径冒充加速，也不把温度首图标为完整气候。
用户体验验收由前端入口提案维护，不在这里保存第二份面板和导航方案。
