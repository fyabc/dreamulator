# 浏览器气候实验台（Pyodide 温度首图）

> **状态**：实验性原型已落地（2026-10-23）。页面 = `/playground`（界面名「气候实验台」），
> 默认隐藏，打开「实验功能」后出现在侧栏。当前只算温度；降水、风场、洋流与 Köppen
> 尚未接入。
> 优先级与后续路线见 [`../roadmap.md`](../roadmap.md)。

## 1 目标

验证「上传高度图 → 在浏览器里得到气候图层、无需服务器」这条产品路线。第一腿只做
**温度首图**：用户拖入一张 PNG/JPEG 高度图，页面在本地用 Pyodide 运行引擎的纯温度
函数，画出年均与逐月温度场，并给出全球均温、面积均值、温度范围与计算耗时。

不做世界创建、CVT 网格、分支、降水/风场/洋流、Köppen 与持久化。这个页面回答的是
交互形态与浏览器计算成本，而不是完整世界构建。

## 2 为什么先做温度

前期 Node/Pyodide 探针已经证明引擎纯函数可以原样在 wasm 里运行，且数值与宿主
CPython 近逐位一致（温度/降水/月度场的差异在 1e-12 量级，Köppen 0/200000 不一致）。
但全气候阶段在 200k 细胞上仍要约 800 s（wasm），其中降水月度预算占约四分之三；
这是算法本身的成本，不是 Pyodide 的倍率问题。

温度阶段独立看只要十余秒（200k 细胞），首图交互完全可行。于是 Gate D 先切出温度
这一腿，验证「加载 → 拖放 → 出图 → 切月」的产品形态；降水与 Köppen 等后续加速
再接入。

## 3 架构

### 3.1 运行时

- Pyodide 314.0.7，从 jsDelivr 按需加载（`pyodide.mjs` + numpy），不进入主 bundle；
- 只加载 numpy，不加载 scipy/pydantic；页面不需要后端，静态站可直接运行；
- 引擎源码以 Vite `?raw` 导入的文本写入 Pyodide 虚拟文件系统：
  - `engine/climate_physics.py`
  - `engine/climate_seasonality.py`
- 温度驱动脚本 `frontend/src/playground/temperature_kernel.py` 只 import 上述两个纯
  函数模块，不碰 `map.climate_simulator`、pydantic 细胞模型或 CVT mesh。

### 3.2 温度链

1. `equilibrium_temperature()` + `surface_temperature()` 给出全球均温；
2. `solve_1d_ebm_temperature()` 给出纬向年均温度，扩散系数按引擎同款
   `D ∝ Ω^-0.3` 缩放；
3. 陆地为单元格应用 `moist_lapse_rate()` + `altitude_lapse_rate()`；
4. `seasonal_heat_capacity()` 按海陆与离岸距离给季节热容（网格 BFS 近似海岸距离）；
5. `monthly_insolation()` + `monthly_temperature()` 给出 12 个月温度。

### 3.3 网格与输入

- 固定 180×90 等距圆柱规则网格（16,200 格），北在上、经度 -180…180；
- 内置地球与 Nacrea 两个示例高度图（从真实高程图面积平均下采样到 180×90，
  8-bit PNG，各约 9 KB），默认载入地球；
- 用户可拖入任意 PNG/JPEG/WebP；图像缩放到 180×90，灰度 0/255 线性映射到「最低/
  最高高程」两个输入框，海平面单独给出；
- 参数面板提供地球与 Nacrea 两组预设（地球在前），以及光度、轨道半长轴、反照率、温室增温、
  轴倾角、公转/自转周期、海平面与递减率开关。

## 4 界面

单页三块：左侧行星参数与高度图投放区，右侧温度场画布、月份滑杆与统计卡片。
导入高度图后、温度图生成前，右侧先显示该高度图的灰度预览，方便用户确认自己载入的是
哪一张图；点击「运行温度首图」后才切换为温度场。月份滑杆在年均与 12 个月之间切换；
温度色标为 -40…+40 °C 的 RdYlBu 风格；海岸线由高程掩膜在网格边界上以细线绘出。

入口：

- 打开侧栏「实验功能」后出现「气候 playground」；
- 或直接访问 `/playground`（静态站为 `#/playground`）。

## 5 验收数据（2026-10-23，1600×1000，默认地球示例）

| 项 | 结果 |
|---|---|
| Pyodide + numpy 加载 | 5.9 s（CDN） |
| 16,200 格温度首图 | 0.19 s |
| 月份切换 | 即时（使用同一份结果） |
| 全球均温（能量平衡） | 13.9 °C |
| 温度场面积均值 | 12.6 °C（含陆地高程递减） |
| 温度范围 | −39 … +27 °C |

Nacrea 示例走同一路径，全球均温约 11.3 °C、面积均值约 10.3 °C。这部分全球均温
来自简化能量平衡链，和完整气候引擎的年均值存在差异；页面把它标为「能量平衡」
而不是引擎最终年均值。

## 6 已知限制

- 只算温度；没有降水、风场、洋流、Köppen、CVT 网格与分支；
- 规则经纬网格与引擎 CVT 网格不是同一口径，适合交互验证，不适合直接比较细胞级结果；
- 首次运行依赖 CDN 与网络；尚未做离线资源包与短码分享；
- 8-bit 高度图只有 256 个高程台阶，细微地形会被量化；
- Pyodide 版本固定为 314.0.7，升级需要复核 CDN 路径、numpy 包与引擎源码兼容性。

## 7 后续路线

1. **Gate D 完整版**：把降水/Köppen 接入的前提是降水预算加速；温度首图先保留为交互
   验证腿。
2. **加载器产品化**：从规则网格过渡到数组原生 CVT mesh（`__slots__` 细胞 shim），
   让浏览器结果与引擎同网格可比；这一步涉及 `map/` 引擎路径，需要先明确归属与
   bundle 交付方式。
3. **资源与分享**：评估 Pyodide 本地镜像/离线包、短码分享（参数 + 高度图摘要）与
   GitHub Pages 的缓存策略。
4. **UI 收口**：高度图范围自动识别、错误提示、移动端拖放、导出 PNG 与图例细化。
