# 浏览器计算路线

> 状态：部分实现，温度实验原型已实现，完整气候与资源产品化仍为候选。
> 立项日期：2026-10-23。

## 目标与已有基础

浏览器计算让作者在本地确认输入并获得预览，无需先启动服务器。
现有温度原型的运行时、网格、输入、界面与限制由[技术参考](../pipelines/browser-playground.md)维护。
首屏入口、导入预览、参数说明、错误反馈与结果阅读由[前端入口提案](frontend-entry.md)统一设计。

## 尚未实现的计算路线

完整气候接入首先需要验证水汽预算的计算成本、守恒与收敛，之后才能决定可接受的网格规模。
数组化球面网格、共享内存 Worker 与 GPU 计算是候选，依据见
[浏览器 GCM 调研](../web-gcm-and-frontend.md)，它们不意味着现有原型已经具备完整世界能力。

运行时本地镜像、离线资源包和可分享输入需要明确加载、缓存、文件保留与结果版本的契约。
它们可以改善浏览器交付，但正式世界与本地预览仍应说明各自的模型和数据来源。

## 验收与不采用的方向

计算后端分别验收宿主与浏览器的数值一致性、守恒、收敛、内存和运行时加载成本。
采用新的并行或 GPU 路线时，先在同输入、同网格上核对结果，再评估交互收益。
不以降低科学口径冒充加速，也不把温度首图标为完整气候。
用户体验验收由前端入口提案维护，不在这里保存第二份面板和导航方案。
