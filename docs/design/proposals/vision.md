## 0. 释名：为什么叫 Dreamulator？

在深入技术之前，有必要重新审视这个名字。它不是一个轻率的合成词，而是我们在感性与理性、文学与工程之间寻找平衡的隐喻。

- **Dream（梦境/幻想）**：代表着架空世界创作者的初衷。那些天马行空的设定、违背现实常理的魔法、神话与史诗，是发散的、浪漫的、充满偶然性与主观色彩的。
- **-ulator（模拟器/演算仪）**：这个后缀带有浓厚的工业与计算色彩，让人联想到 Simulator（模拟器）、Calculator（计算器）或是 Regulator（调节器）。它代表着底层的物理引擎、常微分方程（ODE）与有向无环图（DAG），是收敛的、严苛的、充满决定论的。

Dreamulator 并不是一个让人沉溺于无序幻梦的"造梦机（Dreamer）"，而是一台 **"梦境演算仪"**。它的使命，是将那些虚无缥缈的 Dream，放入严密的 -ulator 中进行推演与约束。我们试图用代码的齿轮，去为无序的想象力赋予可计算的刻度。

## 1. 我们的初衷与困境

Dreamulator 的诞生源于一个简单的愿望：我们能否用严谨的科学法则，去推演一个架空世界的千年史诗？

然而，随着开发的深入，我们不可避免地撞上了一堵名为"知识边界"的墙。无论是气候经济学、地缘政治，还是文明演化，人类现有的理论模型（如 HANDY 或 SDT）都充满了极其粗糙的简化假设。当我们试图用这些残缺的公式去模拟一个鲜活的文明时，必然会遭遇逻辑的断裂与推演的"恐怖谷"效应。

我们深知，以目前的工程能力与人类的认知局限，Dreamulator 永远无法成为一台"完美的历史还原机"。因此，我们必须重新定义它的目标：**它不是一面映射现实的镜子，而是一台为平行宇宙立法的"受控想象引擎（Fantasy Harness）"。**

---

## 2. 核心法则：Fantasy Harness（受控想象）

为了缓解引擎理论知识缺失带来的逻辑崩塌，我们确立了 Dreamulator 的双轨驱动架构：

- **ODE / SDE 作为引力骨架**：我们将已知且确凿的科学法则（如天体物理、地质演化、基础的人口动力学）固化为底层的 DAG 与微分方程。它们构成了世界的"重力"，确保河流不会倒流，承载力不会凭空产生。我们也拥抱随机微分方程（SDE），用概率分布去容纳历史的偶然性。

- **LLM 作为血肉填充**：我们承认代码无法写出史诗，因此引入 LLM。但 LLM 绝不是脱缰的野马。通过严格的 Harness（控制回路），我们限制 LLM 仅在 ODE 输出的状态边界内进行"语义渲染"。在关键因果节点上，代码拥有绝对的否决权；而在非关键的文化、神话与细节描述上，我们允许 LLM 自由发挥，扬长避短。

- **守护轴（Harness）作为第三条轨道**：在「引力骨架」与「血肉填充」之外，守护轴负责校验、审计与设定维护——防止严谨随演化静默漂移（silent drift / stale memory）。见 [harness.md](harness.md)。

## 3. 对待未知的态度：拥抱"粗粒化"

面对那些人类尚未搞清楚、或引擎暂未实现的复杂机制（例如宗教的微观传播、宫廷阴谋的具体博弈），我们拒绝强行编写简陋的启发式规则，因为那只会带来令人反感的自相矛盾。

相反，我们选择**将"无知"转化为"自由度"**。借鉴统计物理中的朗之万方程思想，我们将这些未知的黑盒打包为系统演化中的**输入自变量或随机扰动项**：

- 一场无法被底层模拟的宫廷政变，在引擎中只是一个泊松跳跃（Poisson Jump）；
- 一段未被建模的文化繁荣，在引擎中只是一个带有偏置的有色噪声（Colored Noise）。

我们用世界本身的"自由度"与"偶然性"，去包容引擎的局限。这不仅掩盖了逻辑的断层，反而让推演出的历史充满了真实的颗粒感。

## 4. 开放性：MIT、魔法黑盒与"硬度"的包容

Dreamulator 采用 MIT 协议完全开源，这意味着它不属于任何一个中心化的团队，而是属于所有对世界构建抱有敬畏之心的创作者。

### 从"硬科幻"到"软魔法"的连续光谱

经常有人问：*Dreamulator 这么强调物理法则，它能模拟魔法世界吗？* 答案是肯定的。

Dreamulator 绝不强迫创作者去推导"火球术的热力学方程"。在我们的架构中，**魔法、神迹或超自然现象，完全可以被视为一种"未被解释的外生变量（Exogenous Variable）"或"高阶修饰器（Modifier）"**。

如果您不想深究魔法的原理，只需在文明层注入一个 `Modifier: mana_density`（魔力密度）。引擎不需要知道魔力是什么，它只需要知道：当 `mana_density` 超过某个阈值时，会触发 `Event: magic_awakening`，并改变该区域的农业承载力或战争胜率。**只要魔法的"后果"能被映射到系统的状态变量上，推演就能在逻辑自洽的前提下继续运行。**

### 分支系统作为"多元宇宙的宪法"

不同创作者对"拟真度"的需求是截然不同的。硬核推演者可能希望在 `geological` 层死磕板块运动的摩擦系数；而奇幻小说家可能只想要一个气候宜人的舞台来展开爱恨情仇。

Dreamulator 的 Git 风格分支系统，正是为了包容这种分歧而生的。在 `main` 分支上，我们维护一套基于现实地球的基准物理法则；但在 `branch/high-fantasy` 上，创作者可以随意修改重力常数、引入魔法扰动，甚至关闭部分严苛的生态校验。**分支系统允许不同的"宇宙法则"平行存在、各自演化，互不干涉。**

## 5. 关系即本质：实体与命名的解耦

在大型世界观创作中，"火星（行星）"和"马尔斯（战神）"同名冲突是经典的工程难题。我们的立场是：**在底层，关系比名字更本质。**

借鉴 Wikidata 的 Q-ID 系统和范畴论的思想：

- 每个实体在底层只有一个不变的 **UUID**，它是 DAG 寻址、因果溯源和 Git 合并的唯一锚点。
- **名字只是关系的一种**——它是从实体指向"字符串常量"的一条有向边（态射），且附带上下文（"谁在什么时代这样称呼它"）。
- 罗马人称其为 Mars，希腊人称其为 Ares，汉朝人称其为荧惑——底层指向同一个 UUID，渲染层根据当前上下文自动选择合适的名字。

这不仅是命名冲突的工程解法，更是一种世界观哲学的自觉：**结构就是一切，名字只是凡人眼中的幻象。**

## 6. 相关实体：Moltke Engine

当推演精细化到百万级实体（人物、家族、城邦、事件）时，需要一个独立的实体网络引擎来保障性能。我们预研的 **Moltke Engine**（暂定名）将承担这一角色。

**MOLTKE** = **M**ulti-scale **O**ntology and **L**ogic **T**raversal **K**nowledge **E**ngine

命名致敬老毛奇（Helmuth von Moltke the Elder）与现代总参谋部制度——他创立的"任务式指挥"体系，本质上就是一台处理复杂信息的"人肉计算机"与"知识图谱"。"没有任何作战计划在与敌军主力遭遇后仍有确定性"——这句老毛奇的名言，完美契合了 Dreamulator 拥抱混沌与不确定性的核心哲学。

Moltke Engine 是一个远期目标。在其实装之前，实体管理将在现有 DAG pipeline 中渐进式演进。

## 7. 终极愿景：寻找设定的"混沌边缘"

Dreamulator 不追求绝对的拟真，因为绝对的拟真是一个永远无法到达的渐近线。

我们的目标是寻找复杂系统科学中所说的 **"混沌边缘（Edge of Chaos）"**：

- 如果规则太少、太简单，世界会显得失真且无趣；
- 如果规则太多、太严苛，世界会因为参数冲突而陷入自相矛盾的死锁。

Dreamulator 存在的意义，就是在这两者之间划定一套克制的法则。我们希望为创作者提供一个底座——在这里，决定论的必然性与随机扰动的偶然性交织，最终涌现出那些连我们作为开发者，都未曾预料到的、却严丝合缝的平行宇宙史诗。

## 8. 时间作为一等公民

Dreamulator 的每一层数据本质上都是**随时间变化的场**。从恒星演化（10⁹ 年）到板块漂移（10⁸ 年）、冰期循环（10⁴–10⁶ 年）、生态迁移（10³–10⁶ 年）、再到文明兴衰（10²–10³ 年）——不同的时间尺度交织成世界的历史。

这一愿景的核心是：**将"时间轴"深度嵌入前端**，让创作者可以像拖拽视频进度条一样浏览世界的演化历程。

### 阶段规划

**近期（Phase 3A 完成后）**：
- 地质时间轴：板块漂移快照回放，海陆变迁动画
- 快照存储：差分格式，每步仅存变化 cell，轻量可播放

**中期**：
- 气候与洋流时间序列（预计算，关键时间节点采样）
- 侵蚀-沉积演化序列

**远期**：
- 生态层物种迁移时间轴
- 文明层国家兴衰时间线
- 统一时间控件——切换图层时，时间轴自动切换到对应尺度和单位

这一功能的开销集中在 GPU 纹理更新和快照 I/O。首版地质时间轴仅需增量更新 plate colormap + elevation 纹理，无需全量重新生成。风场/洋流等昂贵计算采用预计算策略，不在地图页面上实时运行。

## 9. 生态位：Dreamulator 不是什么

- **不是"AI 写小说"工具**：LLM 是渲染引擎，不是创作主体。代码负责逻辑，AI 负责文采。
- **不是 World Anvil / Notion 替代品**：我们不提供维基编辑器。Dreamulator 的世界观是**可计算的资产**，不是纯文本文档。
- **不是 SillyTavern 的竞争者**：酒馆做微观角色扮演，Dreamulator 做宏观世界推演。两者在架构上是互补的上下游关系。
- **不是"一键生成世界"的黑箱**：我们提供克制的法则和透明的推演链路，用户保有完全的控制权。

## 10. 扩展功能 backlog

从 `roadmap.md` 合并而来的远期扩展方向（按吸引力而非优先级排列）：

- **交互式世界线浏览器**：类似 GitHub Network Graph，可视化分支树 + 关键事件节点。用户可拖拽时间轴，对比不同分支下的世界演化。
- **实时协作模式**：WebSocket 多人同时编辑一个世界，类 Google Docs 体验 + Git 版本控制。每个创作者的修改实时推送到 DAG 引擎，即时预览下游影响。
- **AI 顾问模式**：用户在 YAML 中设定模糊目标（如"我希望北大陆出现一个游牧帝国"），LLM 分析当前世界状态 → 建议需要修改哪些层级的参数 → 用户确认 → 引擎自动注入 Modifier → 推演 → 生成叙事。
- **世界导出包**：一键导出完整世界为 ZIP（elevation.png + voronoi.json + civilizations.yaml + LLM 生成的 Wiki），导入 TTRPG 工具（[Foundry VTT](https://foundryvtt.com/)、[World Anvil](https://www.worldanvil.com/)）；同时导出视频素材（球面旋转动画 + timelapse 地图变化）。
- **文明演化回放（Timelapse）**：类似《文明》系列的地图回放，从初始地质状态到文明兴衰的完整时间线动画，可直接导出为视频素材。技术路径见 §8 时间轴。
