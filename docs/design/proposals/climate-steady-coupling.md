# 气候层稳态耦合中间态（DAG 中某一步耦合解定点）

> 状态：远期提案（草稿）。定位是**诊断式单向 DAG**（现状）与**全动力学 GCM**
> （`climate-gcm-plan.md`）之间的「第 0.5 步」：不时间步进、不换动力核心，只在 DAG 的
> **某一步**里把一组互相依赖的场解成**稳态定点**。不排优先级、不承诺时间。

## 动机：反复出现的「双向耦合」都是同一条缺失的边

诊断式 DAG 每场只算一次：温度 → 降水（蒸发）这条边有，但**降水 → 温度（干旱度反馈）**
这条边没有。所有被「双向耦合」理由挂起的问题，缺的都是这条反向边：

- **干空气暖**（today.md「干空气暖 +2°C，延后」）：干地表无蒸发冷却，辐射平衡更热——
  温度不知道 P，只能延后。
- **B 方案（E/P 比做大陆度）**（① 诊断结论）：干燥度该由水汽预算自算的 E/P 决定，
  但温度↔E_pot 没耦合。
- **4.2 副热带下沉增温**：现在是单独的 Held-Hou「等面积均质化」预设，不是真正的
  干旱度反馈——真实副热带干区地表温度由辐射-对流平衡设定（Held & Hou 1980 的干对流调整），
  而非自由大气递减率。

这些都是「温度↔降水」这一个耦合环的不同症状。逐个写「聪明预设」去逼近它，边际收益递减、
预设还会打架（地转风打崩降水就是先例）。

## 定位：三个态的边界

| | 时间 | 反馈 | 成本 |
|---|---|---|---|
| **DAG（现状）** | 稳态，每场算一次 | 单向，无反馈 | 秒级 |
| **中间态（本提案）** | 稳态，**某一步耦合解定点** | T↔P 反馈闭合 | 秒～分钟（定点迭代） |
| **GCM（`climate-gcm-plan.md`）** | 瞬态时间步进 | 全部反馈涌现 | 分钟～小时 |

关键区别：中间态是**稳态耦合定点**，不是 GCM 的瞬态时间步进。它只在某一步解一个隐式
方程组到收敛，其余步仍是 DAG 单次。这是比 GCM 小得多的改动——不换动力核心、不加时间轴、
不重采样地形。

## 具体形态：关掉 T↔P 这一环

现状子 DAG：`风场 → 海洋 → 温度 → 降水 → Köppen`。

- **保留单向**：风场、海洋（SST）照旧算一次，作为定点求解的固定输入。
- **改耦合**：把「温度 + 降水」两步合并成一个 **T↔P 定点**：
  - 温度依赖降水：干旱度（如 `1 − E/E_pot`，或 `P/E_pot`）进地表辐射平衡——干地表更热。
  - 降水依赖温度：蒸发源 `E_pot(T)` + 水汽预算 `∇·(Wu) + W/τ = E`（现 `_solve_moisture_budget`）。
  - 迭代到收敛（阻尼）。

这就是把现有的 **Budyko 定点**从「E↔P（温度固定）」推广成「T↔P（温度也耦合）」。
`_solve_moisture_budget` 已经在做局部定点，本提案只是把温度也纳入这个定点。

## 能解决 / 不能解决

**能解决**（都是 T↔P 反馈，可被定点吸收）：

- 干空气暖、B 方案（E/P 大陆度）、「干」判据——不再需要延后，反馈自然涌现。
- 4.2 副热带下沉增温——从单独的 Held-Hou 预设退化为定点收敛出来的干旱度反馈。

**不能解决**（是别的耦合环或别的机制）：

- **① 内陆不干**：这是**传送**问题（u·τ≈3900km 太长），不是 T↔P 耦合。中间态修不了，
  仍需传送参数化（如陆地 τ 缩短）。
- **§7 冬季季风**：这是**风↔温度**这一环（海陆热力对比→季风），是另一个耦合环，
  不在本提案的 T↔P 范围。

## 定点求解设计（草）

1. **变量**：陆格年均温 `T` 与年均降水 `P`（海洋 SST 固定）。
2. **温度方程**：在现有温度 stage 基础上加一项干旱度反馈
   `T += c_arid · f(1 − E_land/E_pot)`，`c_arid` 是干旱增温幅度（量级 ~2-3 °C，对标 4.2-①
   沙漠偏冷 ~3-4 °C），`f` 是干旱度的单调函数（如线性或 `sqrt`）。
3. **降水方程**：现 `_solve_moisture_budget`（Budyko 定点已在内），温度更新后重解。
4. **迭代**：`T₀`（无反馈）→ `P₀ = g(T₀)` → `T₁ = f(P₀)` → `P₁ = g(T₁)` → …，
   阻尼 `T = (1−α)T_old + α T_new`，收敛判据 `max|ΔT| < ε`（Budyko 定点的同一模式）。
5. **共享参数**：`c_arid`、阻尼 `α`、迭代上限对所有世界同一套（同物理纪律），从
   Earth 标定一次、其他世界只差输入。

## 风险与注意

1. **收敛性/多解**：气候有双稳态（冰反照率、植被-降水），T↔P 定点可能振荡或不收敛。
   需阻尼 + 迭代上限 + 从无反馈解（`T₀`）作初值续延，避免跳到错解。
2. **同物理纪律**：迭代策略、阻尼、初值、收敛判据必须所有世界同一套，不能地球特调。
3. **验证**：定点收敛后必须跑 `validate_climate` 全指标 + nacrea 回归，T↔P 反馈的收益
   （沙漠偏暖、B 群系）不能以 P R²/Köppen 退化为代价。
4. **改动面**：温度 stage 目前完全不读降水，加反向边要重排 stage 依赖、改
   `simulate_climate` 主流程（温度/降水两步从顺序改成内层定点）。

## 与 GCM 的边界

- **GCM 是替换**（瞬态全耦合），**中间态是叠加**（在现有 DAG 上改一步为定点），成本低得多。
- 中间态若验证收益不够、或定点不收敛，则回退到 DAG + 继续「聪明预设」，并把 T↔P 反馈
  的完整涌现留给 GCM。
- 判断准则沿用 `climate-gcm-plan.md`：只有当「预设边际收益递减」超过「耦合复杂度」时才切；
  中间态是这两个阈值之间的**低成本试水**——先验证 T↔P 反馈值不值得耦合。

## 实现顺序（若通过）

1. 敏感性/可行性实验：在诊断脚本里手算 T↔P 定点（不动物理引擎），看沙漠偏暖能否
   收敛到观测（对标 4.2-① 的 3-4 °C），以及是否收敛、是否多解。
2. 若可行，把温度/降水两步改成内层定点（`simulate_climate` 主流程重排）。
3. 全量验证（Earth + nacrea 回归）+ 把 `c_arid` 等新参数写入共享配置。
4. 更新 `pipelines/climate-pipeline.md` 与 `climate-validation.md`。
